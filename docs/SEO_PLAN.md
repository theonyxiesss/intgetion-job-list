# ТЗ: SEO-продвижение intgetion.com

Цель — чтобы сайт находили в Google и Яндексе по запросам «remote web3 jobs», «удалённая работа в крипте», «вакансии blockchain developer» и т. п., а вакансии попадали в Google Jobs.

Решения этого ТЗ — D265–D274. Миграции, если понадобятся, — следующий свободный номер после `0028`.

## 2. Задачи основателя (без кода)

1. **Google Search Console**: добавить ресурс-домен `intgetion.com` (подтверждение TXT-записью в DNS), отправить `https://intgetion.com/sitemap.xml`.
2. **Яндекс Вебмастер**: добавить сайт, подтвердить (DNS или мета-тег — код передать разработчику), отправить sitemap, указать регион. Включить «Обход по счётчикам», если поставим Метрику.
3. **Bing Webmaster Tools**: импорт из Search Console одной кнопкой (Bing кормит ещё ChatGPT-поиск и DuckDuckGo).
4. **Vercel → Domains**: `www.intgetion.com` — редирект **308 (permanent)** на `intgetion.com`.
5. Решить по P2: фейковые вакансии удалить с прода (рекомендация — да) и по P4 — оставлять ли импорт в индексе (рекомендация — см. 3.2).
6. Через 2–4 недели после выкладки — смотреть в Search Console «Индексирование страниц» и «Вакансии» (отчёт Google Jobs), ошибки передавать Claude Code.

## 3. Задачи разработки

### 3.1 Гигиена индекса (P2, P7) — сделано (D276, D279)

Готово: `x-default` на всех страницах (D276), `seed-demo.mjs` не работает на проде (D279). Источник 17 выдуманных вакансий найден — тестовые источники импорта «Fictional API Feed» и «Fictional RSS Feed»; сами источники уже выключены. Снять эти вакансии с публикации (запрос для основателя, обратимо — `paused`):

```sql
update public.jobs set status = 'paused'
 where status = 'published'
   and id in (select js.job_id from public.job_sources js
                join public.import_sources s on s.id = js.import_source_id
               where s.name in ('Fictional API Feed', 'Fictional RSS Feed'));
```

Осталось по этому пункту: снятые и истёкшие вакансии сейчас отдают 404 — решить, нужен ли `410` со ссылкой на похожие.

### 3.1a Исходный пункт (для истории) — D265

- Скрипт/админ-действие: снять с публикации вакансии с признаками демо/синтетики (`fictional`, `synthetic`, `вымышлен`, компании `demo-*`). На проде демо-сид не запускать никогда (проверка в `scripts/seed-demo.mjs`: отказ при `VERCEL_ENV=production` или облачном хосте БД).
- `hreflang="x-default"` → `/en` на всех страницах и в sitemap.
- Снятые/истёкшие вакансии: `410 Gone` или `noindex` + ссылка на похожие (не 404 и не редирект на главную). Выбрать и записать в D265.

### 3.2 Импортированные вакансии (P4) — D266

- Вариант по умолчанию: страница импортированной вакансии остаётся `index`, но получает **уникальный блок**: краткая выжимка на нашем языке (навыки, формат, часовой пояс, вилка), «похожие вакансии», данные о компании, ссылка на оригинал. Плюс `canonical` на себя.
- Если источник запрещает индексацию копий (условия фида) — `noindex, follow` для вакансий этого источника. Список источников и их условий — в `docs/content/import-dictionary.md`.
- Метрика успеха: доля проиндексированных страниц вакансий в Search Console.

### 3.3 Google Jobs (P1) — частично сделано (D284)

Готово: IndexNow — при публикации, снятии и продлении вакансии её адрес сразу уходит в Bing и Яндекс (D284). Основателю: придумать ключ (любые 8–128 символов из букв, цифр и дефиса), положить его в `INDEXNOW_KEY` в Vercel (prod и preview) и проверить, что `https://intgetion.com/indexnow-key.txt` отдаёт этот же ключ.

Осталось: Google Indexing API — он работает только с `JobPosting`, то есть нужен хотя бы один собственный поток вакансий; ключ сервисного аккаунта от основателя.

### 3.3a Исходный пункт (для истории) — D267

- Разметка `JobPosting` уже готова — нужен **поток собственных вакансий**: работодатели публикуют сами (`/for-employers`). Задача не кодовая, а продуктовая — см. раздел 4.
- Проверить разметку на одной internal-вакансии в Rich Results Test, исправить предупреждения (`baseSalary`, `applicantLocationRequirements`, `identifier`).
- **Indexing API** Google для вакансий (официально разрешён для `JobPosting`): при публикации/снятии вакансии слать `URL_UPDATED` / `URL_DELETED`. Ключ сервисного аккаунта — от основателя, в env. Для Яндекса и Bing — **IndexNow** (ключ-файл в `public/`, пинг при публикации).

### 3.4 Метаданные и соцсети (P5, P6) — сделано (D277, D278, D297)

Готово: заголовок и описание главной (D277), картинка 1200×630 для всех страниц (D278), своя картинка у вакансии (название, компания, вилка, формат) и у компании (название, число открытых вакансий) — D297. Осталось: свои тексты и картинка для `/jobs/t/*` (сейчас у подборки общая картинка сайта и общий вводный текст).

### 3.4a Исходный пункт (для истории) — D268

- Главная: title вида «Remote Web3 & Crypto Jobs — INTGETION» / «Удалённая работа в Web3 и крипте — INTGETION», description 140–160 символов с ключевыми словами. Тексты — `docs/content/landing-texts.md`.
- `og:image`: статичная для главной и динамическая для вакансии/компании (`opengraph-image.tsx`, `next/og`): название, компания, вилка, формат. 1200×630.
- Тематические `/jobs/t/*`: свои title/description/H1 и `og:image`.

### 3.5 Посадочные страницы под запросы (P9) — сделано (D290–D291, D294–D296)

Готово: страница подборки есть у каждого навыка из справочника (D294), у уровней и типов занятости (D291), у пяти регионов по рабочим часам (D295). У каждой — описание, `canonical`, `hreflang`, RSS, крошки и FAQ с разметкой `FAQPage`; подборка меньше трёх вакансий уходит в `noindex, follow` (D296). Все попадают в sitemap только когда в них есть вакансии.

Осталось по этому пункту: свой вводный текст на 100–200 слов под каждую подборку вместо общей фразы (нужны тексты от основателя или отдельная подготовка), перелинковка на соседние подборки и `/salaries` как подборка «Зарплаты в web3» (сделано отдельно, D260).

### 3.5a Исходный пункт (для истории) — D269–D271

Новые индексируемые страницы-подборки (только если в подборке ≥ 3 вакансии, иначе `noindex`):

- по навыку: `/jobs/skill/solidity`, `/jobs/skill/rust`, … (из справочника навыков, `docs/content/skill-aliases.md`);
- по уровню: `/jobs/t/junior`, `/jobs/t/senior`;
- по региону/часовому поясу: `/jobs/region/europe`, `/jobs/region/latam`, … (из часового пояса вакансий);
- «Зарплаты в web3» `/salaries` — когда Hermes закончит P-SALARY (D260–D264): медианы по ролям, обновляются по данным вакансий.

Каждая страница: уникальный вводный текст 100–200 слов (en и ru), список вакансий, FAQ (3–5 вопросов) с разметкой `FAQPage`, перелинковка на соседние подборки. Все — в sitemap.

### 3.6 Структурированные данные (P10) — D272

- `Organization` (логотип, соцсети) и `WebSite` с `SearchAction` (`/jobs?q={query}`) на главной.
- `BreadcrumbList` на вакансии, компании, подборках.
- Компания: `Organization` с `sameAs` (сайт, LinkedIn, X).

### 3.7 Скорость (P8) — D273

- Уже у Cursor (LCP ≤ 2200 мс). Дополнительно: CLS < 0.1 и INP < 200 мс на странице вакансии и каталоге — замерить и закрепить бюджеты в CI.

### 3.8 Аналитика поиска — D274

- Яндекс Метрика (только при согласии на аналитические cookie, как D219–D220) — нужна для Вебмастера и отчётов по запросам в Яндексе.
- В `/admin/metrics` — блок «Органика»: визиты из поиска по дням (из своих событий аналитики D225–D229, `referrer` = поисковик).

## 4. Контент и внешние ссылки (продвижение)

- **Собственные вакансии** — главный рычаг для Google Jobs: 10–20 компаний-партнёров публикуют напрямую (бесплатно на старте). Ответственный — основатель.
- **Блог/гайды** `/guides` (позже): «Как найти удалённую работу в web3», «Зарплаты Solidity-разработчика 2026», «Как пройти собеседование в крипто-компанию» — 2 статьи в месяц, en и ru.
- **Ссылки**: каталоги стартапов и job-агрегаторов (Product Hunt, AlternativeTo, списки «web3 job boards» на GitHub), профили в LinkedIn/X/Telegram со ссылкой на сайт, партнёрские страницы компаний («Мы нанимаем на INTGETION»).
- **Telegram-канал** с вакансиями — каждая публикация со ссылкой на страницу вакансии.

## 6. Как проверяем (DoD)

- Rich Results Test: `JobPosting` на internal-вакансии без ошибок; `Organization`, `WebSite`, `BreadcrumbList`, `FAQPage` — валидны.
- Search Console через 4 недели: sitemap обработан, ≥ 70 % URL из sitemap проиндексированы, в отчёте «Вакансии» нет ошибок.
- Яндекс Вебмастер: sitemap принят, нет критичных ошибок.
- На проде нет вакансий с «fictional/synthetic»; у всех страниц есть `og:image`, `x-default`; `www` отдаёт 308.
- e2e: каждая новая посадочная страница — 200, есть H1, title, description, canonical, `hreflang`; страница с < 3 вакансиями — `noindex`.
- Lighthouse SEO ≥ 95 на главной, вакансии, подборке.
