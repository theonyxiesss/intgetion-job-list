> Карта: [tz/INDEX.md](INDEX.md) · рядом: [15-notifications.md](15-notifications.md), [10-matching.md](10-matching.md), [12-bot.md](12-bot.md).
> Ответы основателя 2026-10-07: Чикаго / Берлин / Москва — да; порог 0.65 — для обеих сторон; на `/notifications` к галочке Telegram добавить галочку почты.

## 1. Зачем

Утром, когда человек просыпается, агент пишет ему: «есть хорошая
вакансия» — кандидату, «есть подходящий кандидат» — работодателю.
Со ссылкой. Только тем, кто сам включил помощь агента.

## 2. Как устроено: основной cron → триггер → каналы

```
/api/cron/morning-briefs  (каждые 15 мин, ОСНОВНОЙ)
   │  какой слот сейчас утро? не на паузе? сегодня ещё не отработал?
   ▼
подбор: кандидатам — вакансии, работодателям — кандидаты (скор ≥ 0.65)
   │
   ▼  ТРИГГЕР: одна запись на человека в transaction
notifications (matches.digest / company.candidates_digest)
   + email_jobs (если галочка почты включена)
   + postSystemEvent → заметка агента в /chat
   │
   ├─► /api/cron/telegram (каждые 5 мин, уже есть, D237)
   │      → сообщение в Telegram-бот со ссылками, если галочка Telegram
   └─► почтовый диспетчер 9A (уже есть) → письмо, если галочка почты
```

**Основной cron сам ничего не отправляет.** Он решает «кому и что» и
создаёт уведомление — это и есть триггер. Отправку делают уже
работающие механизмы: Telegram-диспетчер (`runTelegramDispatch`) и
почтовая очередь (`deliverInTransaction` → 9A). Ретраи, отписка,
пропуск Telegram-заглушек вместо почты (D217) — достаются бесплатно.

## 3. Три слота

| Слот | Часовой пояс | Время по умолчанию | Кто попадает (смещение UTC сейчас) |
|------|--------------|--------------------|------------------------------------|
| `americas` | `America/Chicago` | 08:00 | −10 … −3 |
| `europe` | `Europe/Berlin` | 08:00 | −2 … +2 |
| `cis` | `Europe/Moscow` | 08:00 | +3 … +14 |

- Слот человека — по `timezone` профиля (кандидата; у работодателя — по
  `timezone` пользователя, иначе компании). Нет таймзоны → `europe`.
- Время, пояс и пауза слота меняются в админке (§7).
- **Почему один cron, а не три в `vercel.json`:** расписание Vercel Cron
  меняется только деплоем. Один cron каждые 15 минут читает таблицу
  слотов — время из админки начинает действовать сразу.
- Слот «пора», когда локальное время слота ≥ заданного и < заданного +
  2 часа (окно догона, если cron пропустил тик), и боевого запуска за
  эту дату ещё нет.

## 4. Кто получает

### Кандидат

- Включён флаг **«Агент подбирает мне вакансии»**. По умолчанию **включён**
  у всех кандидатов (D340): старая рассылка шла всем, никто её не теряет;
  выключить — переключателем из подфазы B.
- Вакансии: опубликованы после прошлой сводки (первая — за 7 дней),
  скор ≥ **0.65**, без отклика и не скрытые, максимум 5, лучшие первыми.
- Пусто → ничего не шлём.

### Работодатель

- Член компании (recruiter+), включён флаг компании **«Агент подбирает
  кандидатов»** (по умолчанию выкл.).
- По активным вакансиям компании — кандидаты со скором ≥ **0.65**,
  появившиеся/обновившие профиль после прошлой сводки, не откликнувшиеся.
  Максимум 5 на сводку, по всем вакансиям вместе, лучшие первыми.
- Приватность ([05-privacy-rights.md](05-privacy-rights.md)): только
  обезличенная карточка (роль, опыт, навыки, причина совпадения), без
  контактов до взаимного интереса. Кандидат, скрытый от работодателей
  или без флага поиска, не попадает. Ссылка ведёт на страницу вакансии
  в кабинете работодателя со списком подходящих.
- Новый тип уведомления `company.candidates_digest` в каталоге
  (`notifications/lib/catalog.ts`): inapp ✅, telegram по галочке,
  email по галочке.

## 5. Что приходит

- **Telegram-бот:** вступление агента + до 5 строк «Название — Компания
  · почему подходит» и **ссылка на каждую вакансию** (у работодателя —
  на карточку кандидата в кабинете). Внизу «Все подходящие» и «Выключить».
- **Почта:** то же в шаблоне D330, ссылка отписки.
- **`/chat`:** заметка агента «Нашёл N вакансий» со ссылкой на `/matches`.
- **In-app:** уведомление в колокольчике (всегда, если включён флаг агента).
- Вступление может писать LLM (OpenRouter, D317) только по готовым
  данным карточек; ошибка/лимит → шаблон из `messages/{en,ru}.json`.
  Вакансии/кандидатов LLM не выбирает.
- Язык — `users.locale`. Одна сводка на человека на слот-день во все
  включённые каналы.

## 7. Админка `/admin/briefs`

Раздел в существующей админке (`src/app/(admin)/[locale]/admin/`), API
под `src/app/api/admin/briefs/`.

1. **Слоты:** три строки — часовой пояс (IANA), время (ЧЧ:ММ, шаг 15 мин),
   вкл/пауза, «следующий запуск» (по UTC и по местному).
2. **Глобальная пауза** — один выключатель на всё.
3. **Запустить сейчас** по слоту: «сухой прогон» (считает, кому ушло бы,
   ничего не шлёт) и боевой (с подтверждением; если сегодня уже был —
   отказ, защита от двойной рассылки).
4. **Журнал запусков:** слот, дата, начало/конец, проверено кандидатов /
   работодателей, отправлено, пусто, ошибок, сухой/боевой; 30 дней.
5. **Счётчики подписок:** сколько с флагом агента, сколько с Telegram,
   с почтой — по слотам.
6. Всё пишется в `audit_log`. Доступ — только роль admin.

## 8. Данные (миграция)

- `brief_slots`: `id` (`americas|europe|cis`), `timezone`, `local_time`,
  `enabled`, `updated_by`, `updated_at`. Сид: три строки из §3.
- `brief_settings` (одна строка): `paused`.
- `brief_runs`: `slot_id`, `slot_date`, `dry_run`, `started_at`,
  `finished_at`, счётчики, `error`; unique (`slot_id`, `slot_date`)
  where `not dry_run`.
- `brief_deliveries`: `user_id`, `audience` (`candidate|employer`),
  `slot_date`, `item_ids`, `notification_id`; unique (`user_id`,
  `audience`, `slot_date`). Заменяет `last_digest_at` как защиту от
  повтора (поле оставить до удаления старого cron, потом депрекейт).
- Флаги: `candidate_profiles.agent_briefs_enabled`,
  `companies.agent_briefs_enabled`.
- RLS: новые таблицы — только service role; админ читает через API.

## 10. OPEN QUESTIONS

1. Работодателю нужна кнопка «пригласить откликнуться» в сводке? Пока —
   нет (только ссылка в кабинет); кнопка — отдельная задача.
2. Если работодатель живёт в одном поясе, а компания в другом — берём
   пояс пользователя (принято консервативно, можно поменять).
3. **Пояс работодателя (D365, миграция `0040`).** `companies.timezone`
   (IANA, NULL → `europe`), поле в профиле компании, проверка
   `isIanaTimeZone`. Пояс по стране не выводится, у `users` колонки нет.
   Сводка берёт пояс компании; если у человека несколько компаний и пояса
   разные или пустые — `europe` и лог `no_employer_time_zone`.
4. **«Кандидат в поиске» (D365, миграция `0041`).**
   `candidate_profiles.job_search_status`: `active` (по умолчанию, все
   существующие), `passive`, `not_looking`. Сводка работодателя берёт
   `active` и `passive`; `is_hidden` по-прежнему отсекает. `is_hidden` и
   `availability_date` флагом поиска не считаются. Переключатель — в
   профиле кандидата.
