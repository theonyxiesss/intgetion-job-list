**Статус (2026-10-27):** модель цели, связка с инструментами, панель, управление паузой и удалением, очистка по TTL — выполнены по коду и тестам. Живой сценарий под входом не выполнен. Commit — только локальный; push и выкладка — по отдельному «да».

**Основа:** [ТЗ 35, этап 3](35-spoki-agent-roadmap.md#этап-3--вести-цель-через-сервисы-платформы); [ТЗ 38](38-spoki-stage-spec-guide.md). D544 (проектная записка), D550 (первый сценарий и TTL 30 дней), D551–D553, D558. Правило из D550: сохранение только по явному выбору вошедшего пользователя.

## 1. Что проверено

Офлайн: тесты `job-goal*` в `src/modules/bot/__tests__/` — `job-goal.test.ts`, `job-goal-session.test.ts`, `job-goal-control.test.ts`, `job-goal-tools.test.ts`, `job-goal-scenarios.test.ts` — входят в 365 тестов модуля бота (всего 56 файлов прошли, 3 пропущено). `pnpm typecheck` — exit 0. Ни один из тестов не ходит в реальную базу или модель: вызовы инструментов и хранилище подменены.

## 2. Что осталось

1. **Живая проверка под входом** — блокер: квота Supabase. Без неё не подтверждаются пункты 6, 8 и сохранение между посещениями.
2. **Пункт 4 (сравнение кандидатов для цели)** — не реализован. Решение: делать ли в этапе 3 или отложить. Блокер: решение основателя.
3. **Пункт 7 (ограничение и предложение альтернативы)** — нужен тест или сценарий. Блокер: код, решается без основателя.
4. **Другие маршруты (услуги, UGC, события)** — по D550 выбран только первый маршрут. Расширение — отдельная подфаза и решение основателя.
5. **Очистка истёкшей цели без чтения** — сейчас только при следующем чтении. Блокер: решение, нужен ли отдельный cron (миграции не требуется).
6. **Хранение в облаке** — блокер: вход и облачная база.

## 3. Критерии приёмки

- [ ] Пункты 1–9 имеют статус «выполнено» либо «не проверено» с причиной.
- [ ] Пункт 4 решён: реализован или вынесен в отдельную подфазу с решением основателя.
- [ ] Пункт 7 подтверждён тестом.
- [ ] Вошедший сценарий под входом: создание, показ, сохранение, пауза, продолжение, удаление — с датой и скриншотом.
- [ ] Гостевая цель живёт только в текущей сессии; после входа она не переносится без выбора.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test` — зелёные.

## 4. Что не входит

- Новая таблица или миграция (без отдельного ТЗ и «да»).
- Автоматическое сохранение цели без выбора пользователя.
- Внешний поиск (этап 5).
- Изменение модели и промпта по этапу 2.
- Отправка, отклик, оплата без подтверждения.

## 5. Правила выпуска

- Миграции нет. Если понадобится — отдельное ТЗ, «да» на миграцию и на облако.
- Commit — по «да». Сейчас локальный.
- Push и выкладка — отдельные «да». Хранение в облачной базе — отдельно.
