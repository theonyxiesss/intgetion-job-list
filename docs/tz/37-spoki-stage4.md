## 2. Что остаётся открытым

1. **Живая проверка под входом.** Блокируется снятием ограничения Supabase (квота трафика). Без неё нельзя подтвердить требования 5 и 6 на реальных данных и просмотреть карточки вошедшего пользователя.
2. **Живая проверка Telegram.** Нужен вошедший аккаунт с привязанным Telegram. Сейчас подтверждены только тесты `telegram-agent.test.ts`.
3. **Надпись ссылки в Telegram.** Для любой ссылки блока используется «Открыть». Для страницы тарифов или услуги это может сбивать. Решение — отдельная подпись из серверного allowlist; без согласования текстов во всех языках не менять.
4. **Проверка вёрстки на телефоне.** Узкая ширина 446 px проверена в D542; 390 px и клавиатура при вводе не проверены.

Пункты 1–2 и 4 не закрываются кодом. Пункт 3 — выбор основателя по тексту.

## 3. Критерии приёмки этапа 4

- Все требования 1–8 ТЗ 35 имеют подтверждение: тест, живой просмотр или явная запись «не проверено».
- `pnpm typecheck`, `pnpm lint`, `pnpm test` зелёные; `pnpm build` — перед выкладкой.
- Интеграционные и e2e — через CI (`supabase start`), не локально.
- После живой проверки на сайте — запись в `CURRENT.md` и `OPEN_TASKS.md`.
- Commit и push — только по «да» основателя; выкладка на production — отдельным «да».

- Графики.

- Интернет-поиск (этап 5).
