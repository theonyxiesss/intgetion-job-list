# 33. D523 — Spoki Interactive UI (проект)

Основатель 2026-10-21: Spoki отвечает не только текстом, но и интерактивными компонентами (карточки, калькуляторы с ползунками, сравнения, таблицы, формы, прогресс, раскрывающиеся блоки, графики) и сам решает, когда что показать. Без произвольного JS/HTML от модели, через существующий Spoki и его инструменты, с подтверждениями для реальных действий, с сохранением в истории, адаптивно, в стиле INTGETION, с текстовой заменой в Telegram. **Только проект. Реализация — после отдельного согласования.** Основа — ветка `claude/spoki-core-stage1` (D520–D522).

Обозначения: **[факт]** — проверено в коде; **[решение]** — предложение.

## 1. Аудит: как чат показывает ответы сейчас

- **[факт] Один большой клиентский компонент.** `src/components/bot/chat.tsx` — 1784 строки: поток, история, 15 видов записей (`Entry`: `user`, `assistant`, `event`, `notice`, `jobs`, `matches`, `offer`, `fill_choice`, `ugc_join`, `freelance_services`, `freelance_link`, `ugc_brief_draft`, `freelance_service_draft`, `job_draft`, `confirm`), их отрисовка и действия. Вспомогательные: `chat-markdown.tsx` (Markdown без сырого HTML, D514), `freelance-card.tsx`, `account-card.tsx` (тела карточек подтверждения), `thinking-status-line.tsx`.
- **[факт] Поток событий** (SSE, `BotEvent` в `conversation.ts`): `token`, `tool_start`, `tool_result { name, kind, data }`, `confirm_request`, `error`, `signup_hint`, `resume_ack`, `fill_choice`, `profile_saved`, `done`.
- **[факт] Откуда берутся карточки.** Инструмент возвращает `client: { kind, data }` (`ToolOutcome`), сервер шлёт его как `tool_result`, а `chat.tsx` для каждого `kind` вручную превращает данные в `Entry`. Данные приходят из сервисов, а не из текста модели. Модель пишет только Markdown.
- **[факт] Защита.** Markdown без HTML; ссылки — пути сайта или https; карточки подтверждения с хешем аргументов (`bot_confirmations`); пути карточек-ссылок строит сервер (`offerPath`, `fillPaths`), модель называет только действие.
- **[факт] История не хранит карточки.** `GET /api/bot/conversation` отдаёт только текст (`user`, `assistant`, `system_event`). После перезагрузки остаются открытые карточки подтверждения (`pendingConfirmations`), готовые черновики (перечитываются из таблиц) и ссылка «следующий шаг» UGC. Вакансии, услуги, предложения тарифов пропадают. Текст переписки живёт 24 часа (D471).
- **[факт] Telegram.** `render()` в `telegram-agent.ts` вручную переводит часть видов (`jobs`, `freelance_services`, `ugc_campaign`, `freelance_order`, `fill_choice`, `offer`, `job_draft`, `confirm_request`) в текст и кнопки-ссылки; неизвестный вид молча пропадает.
- **[факт] Кит интерфейса.** `src/components/ui/`: `Stat`/`StatRow`, `Table`/`Th`/`Tr`/`Td`, `Choice`/`Switch`, `LinkTabs`, `Button`, `Badge`, `Dialog`, `Reveal` (уважает «меньше движения»). Библиотек графиков и анимаций нет; CSP запрещает inline-стили (график — SVG с атрибутами и классами Tailwind).
- **[факт] Данные для расчётов уже есть**: цены тарифов (`src/config/pricing.ts`, `billingMe`), вилка вознаграждения UGC (`ugc_price_range`), вилка цен фриланса (`freelance_price_range`), цены пакетов услуг.

**Чего не хватает:** единого формата компонента, проверки данных на клиенте (сейчас приведение типов), версии формата, хранения в истории, защиты от устаревших данных, общего пути для Telegram; новый вид = правки в трёх местах.

## 2. Архитектура

Generative UI — часть существующего хода Spoki, не отдельная система. Два источника компонентов, один формат, один реестр.

```
ход Spoki ─┬─ инструмент данных (search_jobs, find_services, get_ugc_summary …)
           │        └─ ToolOutcome.client ─► сборщик блока на сервере ─┐
           └─ show_ui (новый инструмент ядра, для модели)              │
                    └─ проверка схемы + данные платформы ──────────────┤
                                                                       ▼
                                   UiBlock (zod, версия, fallback) ─► SSE `ui` ─► BlockRenderer (React, реестр)
                                              │                                     │  ползунки: локальный расчёт
                                              └─► bot_messages (история)            └─ кнопки: reply | link | action → /api/bot/ui/action
                                              └─► Telegram: fallback-текст + ссылка        └─ callTool → права, карточка подтверждения (D520)
```

### 2.1 Формат блока `UiBlock` (v1)

```ts
type UiBlock = {
  v: 1;
  id: string; // uuid, выдаёт сервер
  component: UiComponentName; // только из реестра
  props: UiProps[UiComponentName]; // строгая zod-схема компонента
  source: { kind: "tool" | "model"; tool: string; at: string; ttlSec: number };
  fallback: { text: string; link?: SitePath }; // Telegram, чтение с экрана, устаревший клиент
  actions?: UiAction[]; // только типы из списка ниже
};

type UiAction =
  | { id: string; type: "reply"; label: string; text: string } // отправить готовую реплику
  | { id: string; type: "link"; label: string; path: SitePath } // путь сайта из белого списка
  | { id: string; type: "action"; label: string; tool: string } // сервер вызывает инструмент по id блока
  | { id: string; type: "refresh"; label: string }; // перечитать данные блока
```

- Модель **никогда** не присылает HTML, JS, стили или URL. Только имя компонента и параметры по схеме.
- Строки в `props` рисуются как текст. Ссылки — только `SitePath` (тот же белый список, что `offerPath`).
- Аргументы инструмента для кнопки `action`/`refresh` хранятся на сервере вместе с блоком; клиент присылает только `blockId` и `actionId`.

### 2.2 Реестр компонентов

- `src/modules/bot/ui/registry.ts` (общий для сервера и клиента): для каждого компонента — zod-схема `props`, версия, `ttlSec`, допустимые действия, `fallback(props, locale)` (текст для Telegram и чтения с экрана), источник (`tool` — только из данных платформы; `model` — можно запросить через `show_ui`).
- `src/components/bot/blocks/` (клиент): по файлу на компонент и `BlockRenderer`. Блок с неизвестным компонентом, другой версией или неверными `props` показывает `fallback.text`.
- Существующие виды (`jobs`, `offer`, `fill_choice`, черновики) переезжают в реестр по одному; старые `tool_result` продолжают работать на переходный период.

### 2.3 Кто решает, что показать

- **Данные платформы → блок строит сервер.** После инструмента данных `blocksFrom(tool, outcome)` собирает блок из `outcome.client`. Права уже проверены инструментом. Модель не может подменить цифры.
- **Модель выбирает вид для объяснения → инструмент `show_ui`** (ядро маршрутизации D522, один на все компоненты, вход — дискриминированное объединение). Разрешено только то, где модель не придумывает факты:
  - `calculator` — формула из закрытого списка + стартовые значения в пределах схемы; цены и вилки сервер подставляет сам (тарифы, вилка UGC, цена пакета);
  - `compare_plans` — какие тарифы сравнить; цены и «ваш тариф» — с сервера (`PRICING`, `billingMe`);
  - `choice` — варианты ответа кнопками (обобщение `fill_choice`/`offer`);
  - `details` — раскрывающиеся разделы текста.
    Графики и статистика модель не запрашивает: только из инструментов данных.
- Промпт: короткое правило «когда сравнение, расчёт или выбор — `show_ui`; когда вопрос — текст; не пересказывай карточку словами».

### 2.4 Интерактив без вызова модели

- Калькуляторы — чистые функции в `src/lib/calc/` (`ugcBudget`, `freelanceOrder`, `hiringCost`), общие для клиента (ползунки пересчитывают мгновенно) и сервера (текст для Telegram, проверка входа). Формула выбирается по id, модель код не присылает.
- Переключатели (месяц/год у тарифов), сортировка и фильтр таблицы, раскрытие блоков — локальное состояние клиента.

### 2.5 Действия с данными

- Новый маршрут `POST /api/bot/ui/action { blockId, actionId, values? }`: находит блок в истории **этого пользователя и этой нити**, берёт инструмент и аргументы с сервера, `values` — только для полей, которые схема блока помечает как вводимые человеком (ползунки, поля формы), и проверяет их схемой инструмента.
- Дальше — `callTool` хода: чтение выполняется сразу; запись получает **ту же карточку подтверждения** (D520) и попадает в журнал (D521). Заказы, оплаты, публикации и отклики — только так.
- `refresh` перечитывает данные тем же инструментом с правами пользователя и возвращает новый блок.
- Лимит запросов (`botUiAction`, как `botFeedback`); действие не тратит дневной лимит сообщений, если не вызывает модель.

### 2.6 История, восстановление, устаревание

- Блок сохраняется строкой `bot_messages` (`role: assistant`, `content` = `fallback.text`, `tool_call.ui` = блок). Модель в истории видит короткий текст, а не JSON. `GET /api/bot/conversation` отдаёт `ui`, клиент рисует блок после перезагрузки.
- Срок жизни — как у переписки (24 ч, D471): блок исчезает вместе с текстом. Открытые карточки подтверждения восстанавливаются, как сейчас.
- Устаревание: `source.at` + `ttlSec` компонента (вакансии и услуги — 1 ч, статистика — 5 мин, тарифы — 24 ч). После срока блок помечен «Данные на 14:05 · Обновить», кнопки записи отключены до обновления. Сервер всё равно перепроверяет состояние при действии (карточка, `preview`, D515).

### 2.7 Telegram

- `render()` получает одно общее правило: блок → `fallback.text` + кнопка-ссылка `fallback.link` (путь сайта). Калькулятор в Telegram — текст с расчётом для стартовых значений и ссылкой «Посчитать на сайте».
- Новые компоненты в Telegram не требуют кода.

### 2.8 Вид, адаптивность, движение, доступность

- Только токены и кит INTGETION (`Table`, `Stat`, `Choice`, `Button`, `Badge`), `rounded-lg` карточки, тонкие линии, один акцент — как остальной сайт. Графики — свои SVG (столбцы, линия, полоса прогресса), без новой зависимости.
- Телефон: таблицы и сравнения — стопкой карточек, ползунки во всю ширину, цели 44 px, без горизонтальной прокрутки.
- Движение: 150–250 мс (`transition`), появление блока и смена чисел — только без «меньше движения» (`Reveal`, `motion-safe:`).
- Ползунок — нативный `input type="range"` с подписью и значением; пересчитанный итог — `aria-live="polite"`; у графика — таблица данных для чтения с экрана.

## 3. Компоненты MVP

| #   | Компонент       | Источник                           | Где появляется                                    | Действия                                                                            |
| --- | --------------- | ---------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 1   | `job_cards`     | `search_jobs`, `get_matches`       | поиск работы                                      | Открыть (link), Сохранить (action, прямая запись), Откликнуться (action → карточка) |

| 4   | `calculator`    | `show_ui` + данные сервера         | «сколько будет стоить», «бюджет», «Hire или Team» | ползунки, мгновенный пересчёт, «Создать бриф / Разместить» (reply или link)         |
| 5   | `choice`        | `show_ui`                          | выбор из вариантов                                | reply / link                                                                        |
| 6   | `progress`      | черновики (`patch_*_draft`)        | заполнение вакансии, брифа, услуги                | что заполнено, чего нет, Открыть форму                                              |

Формулы калькулятора MVP: `ugc_budget` (роликов × вознаграждение, подсказка из вилки UGC), `freelance_order` (пакет услуги, срок, правки), `hiring_cost` (вакансий в месяц × Hire $79 против Team $199). Все цены — из конфигурации сервера.

**Этап 2:** `chart` (воронка UGC из `get_ugc_summary`, статусы откликов), `table` (сравнение услуг или вакансий бок о бок), `form` (поля черновика прямо в чате с сохранением через `patch_*_draft`; отправка — карточкой), `stats` (свои показатели с периодом).

**Проверки:** модульные тесты схем и формул (крайние значения, отказ неверных `props`), тест `BlockRenderer` (неизвестный компонент → текст), тесты маршрута действия (чужой блок → 404, запись → карточка, `values` вне схемы → 400), тест Telegram-замены, eval: «сравни тарифы» → `compare_plans`, «сколько стоят 5 роликов» → `calculator`, «найди вакансии» → карточки, «привет» → текст. Браузер: телефон и компьютер, «меньше движения», клавиатура.

**Выключатель:** `SPOKI_INTERACTIVE_UI=false` — сервер не шлёт `ui` и не предлагает `show_ui`, блоки из истории рисуются текстом `fallback`.

## 6. Риски

| Риск                             | Мера                                                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Модель «рисует» выдуманные цифры | данные платформы — только из инструментов; `show_ui` принимает лишь входы калькулятора и выбор; цены подставляет сервер |
