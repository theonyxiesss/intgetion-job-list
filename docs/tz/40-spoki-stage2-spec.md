Оценщик ответов (C4, ТЗ 36): флаг `JEV_EVAL` читается в `src/modules/bot/__tests__/answer-eval-live.test.ts` (строка 30). Запуск — `scripts/eval-answers.mjs`, который ставит `ANSWER_QUALITY_LIVE=1` и передаёт `JEV_EVAL` дочернему процессу. Без флага оценщик работает только по шаблонам. Подтверждено 2026-10-27 чтением кода, не запуском.

Локальная правка 2026-10-27 (ТЗ 40, пункт 3): в `answer-eval.ts` сузили правило «ответ нашёл результат» при пустой выдаче. Раньше «Here are some tips» и «I haven't found a…» считались находкой или не считались честным отказом. Теперь «here are» засчитывается только перед словами jobs, services, events, offers, gigs, providers, matches, candidates. «found a» не засчитывается после «n't / not / never». Добавлены фразы честного отказа «haven't found», «have not found», «hasn't found», «has not found». Тесты: `answer-eval.test.ts`, 2 новых набора (принятие и отказ). Это гипотеза о причине `freelance-empty-en`, не подтверждение: сохранённый baseline не содержит текст ответа, поэтому сверить с реальным ответом нельзя.

## 2. Что осталось

1. **Живой baseline модели** — блокер: решение основателя. Нужно новое явное «да» на передачу в OpenRouter с точным payload (системный промпт и схемы инструментов) и лимитом 20 запросов. Автоматическая проверка внешней передачи ранее отклонила такой запрос.
2. **Пороги качества** — блокер: решение основателя. Предложение в отчёте 2026-10-27, не утверждено.
3. **Два случая без разбора** — `freelance-empty-en` (empty_result_claim) и `account-found-en` (нет факта «Polish C1»). Блокер: код или eval-случай, решается без основателя, если порог не меняется.
4. **Проверка D554 на сайте** — гостевой чат на проде 2026-10-27 отвечал «Агент не смог ответить». Блокер: выкладка (отдельное «да»).
5. **Флаг `JEV_EVAL`** — закрыто чтением кода (см. выше). Живой запуск оценщика — только с пунктом 1.
6. **Ветка `claude/llm-fallbacks` (D527)** — слияние по указанию основателя не трогается. Блокер: решение основателя.

## 4. Что не входит

- Смена провайдера или добавление платной модели без отдельного согласования бюджета (ТЗ 35).
- Изменение промпта или fallback по одним синтетическим ответам (D543).
- Интернет-поиск (этап 5).
- Новые зависимости.

## 5. Правила выпуска

- Живой прогон модели — только после «да» на payload и лимит. Без этого не запускать.
- Commit — по «да». Сейчас локальный, только файлы этапа.
- Push и выкладка D554 — отдельные «да». Ветка `claude/llm-fallbacks` сливается только по указанию основателя.
- Стоимость и лимиты провайдера: фиксировать до запуска.
