## 2. Что осталось

1. **Выбор провайдера** — блокер: решение основателя. Варианты с условиями, лимитами и стоимостью готовятся отдельной записью (без регистрации и без ключей).
2. **Учётные данные и стоимость** — блокер: регистрация и согласие основателя. Ключи — только в `.env.local` и Vercel production, не в git.
3. **Состав передаваемого запроса** — блокер: решение основателя (какие поля уходят провайдеру). Без явного согласия на конкретную передачу персональных данных не отправлять.
4. **Серверный инструмент и карточки** — блокер: пункты 1–3. Код не пишется до них.
5. **Тесты согласия** — можно сделать без провайдера: проверка, что без «да» внешний вызов не происходит. Блокер: нет, делается сейчас.

## 3. Критерии приёмки

- [ ] Провайдер выбран основателем и записан в `DECISIONS.md` с условиями и стоимостью.
- [ ] Без согласия внешний вызов не выполняется (тест на сервере и в UI).
- [ ] Передаваемый запрос описан, персональные данные не уходят без отдельного согласия.
- [ ] Результаты показаны карточками с источником; неизвестные поля — «не указано».
- [ ] Ключи не попадают в git, логи и чат.
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` — зелёные.
- [ ] Живой поиск подтверждён после выкладки, с отдельным «да».

## 4. Что не входит

- Выбор платного провайдера и подписка без отдельного согласования (ТЗ 35).
- Автоматические обязательства от имени пользователя.
- Отправка персональных данных без согласия.
- Изменения этапов 1–4.

## 5. Правила выпуска

- Провайдер и ключи — только по решению основателя. Ключи — в Vercel production и `.env.local`.
- Commit — по «да». Сейчас локальный, только файлы этапа.
- Push и выкладка — отдельные «да».
- Стоимость и лимиты — до первого запроса.
