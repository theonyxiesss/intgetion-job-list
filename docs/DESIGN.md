# ТЗ дизайна INTGETION JOB LIST

Версия 1.0, 2026-10-03. Документ обязателен для всех агентов, которые трогают интерфейс. Решения по дизайну — D140–D149 и D155–D159 (UI-2) в `docs/DECISIONS.md`. Если что-то здесь расходится с `docs/TZ_INTGETION_v6.md` по функциональности — прав ТЗ; если по внешнему виду — прав этот документ.

---

## 0. Идея в одном абзаце

Интерфейс в эстетике аэрокосмических сайтов: тёмный «космос» по умолчанию, строгая монохромная типографика, заголовки капслоком с широкой разрядкой, тонкие линии вместо теней и плашек, прямые углы, много воздуха, данные подаются как телеметрия (моноширинные цифры, подписи-метки). Ориентир по настроению — сайт SpaceX: чётко, спокойно, без украшательства. Мы **не** копируем чужие логотипы, шрифты, фотографии, тексты и названия — только принципы.

Ощущение, которого добиваемся: «центр управления полётом для поиска работы». Пользователь видит факты (зарплата, часовой пояс, формат, совпадение) — быстро, без шума.

---

## 1. Принципы

1. **Монохром + один сигнал.** Почти всё — оттенки чёрного и белого. Цвет появляется только чтобы сообщить статус (успех, предупреждение, ошибка, «новое»). Никаких декоративных градиентов на кнопках.
2. **Типографика вместо украшений.** Иерархию строят размер, регистр, разрядка и вес шрифта. Не иконки, не цветные плашки, не тени.
3. **Линии, а не коробки.** Разделители 1 px, рамки 1 px. Тени не используются. Скругления — 0 (исключение — аватар/круглые индикаторы).
4. **Данные как телеметрия.** Числа, даты, часовые пояса, зарплаты, ID — моноширинным шрифтом с табличными цифрами. Подпись поля — маленькая капслоком над значением.
5. **Тишина.** Одна главная кнопка на экран. Вторичные действия — контурные или текстовые. Пустое пространство — часть композиции.
6. **Движение — только по делу.** Плавные короткие переходы (150–250 мс), без прыжков и параллакса. При `prefers-reduced-motion` всё движение отключается.
7. **Доступность не обсуждается.** Контраст AA (текст ≥ 4.5:1, крупный ≥ 3:1), фокус всегда виден, кликабельная зона ≥ 44×44 px, всё работает с клавиатуры. Текущие e2e с axe должны оставаться зелёными.

## 2. Бренд

### 2.1 Название и знак

- Словесный знак: `INTGETION`, капслок, шрифт display (раздел 4), разрядка `0.24em`, вес 600. Рядом мелко `JOB LIST` той же гарнитурой, вес 400, `opacity` 0.7 — только в шапке на ширине ≥ 768 px.
- Графический знак (свой, оригинальный): окружность-орбита 1.5 px и точка-спутник на ней под углом 45°. Монохромный, рисуется SVG-компонентом `<Logo />` с `currentColor`. Размеры: 20 px в шапке, 32 px в favicon, 96 px на пустых состояниях/404.
- Favicon: тот же знак на чёрном квадрате, `src/app/icon.svg` (Next.js подхватывает сам) + `apple-icon.png` 180×180 (генерируется из SVG на этапе UI-1, не скачивается).
- Запрещено: использовать логотипы, ракеты, силуэты кораблей, названия и шрифты SpaceX или других компаний.

### 2.2 Голос текста

Коротко, утвердительно, без восклицаний. Метки — существительные («ЗАРПЛАТА», «ЧАСОВОЙ ПОЯС»), кнопки — глаголы («Откликнуться», «Сохранить»). Тексты в `src/messages/*.json` пишутся **обычным регистром**; капслок делает CSS (`uppercase`), иначе ломаются доступные имена, e2e-селекторы и экранные дикторы.

### 3.2 Светлая тема («дневной режим»)

Та же структура, инвертированная: `--bg #FFFFFF`, `--surface #FAFAFA`, `--surface-2 #F2F2F3`, `--line #E4E4E7`, `--line-strong #C9C9CF`, `--fg #0A0A0A`, `--fg-muted #52525B`, `--fg-subtle #71717A`, `--accent #000000`, `--accent-fg #FFFFFF`, `--signal #2F5BD3`, `--success #0F8A5F`, `--warning #A86400`, `--danger #C62828`.

Переключатель темы уже есть (`theme-toggle.tsx`, атрибут `data-theme`, системная тема по умолчанию). **Меняем умолчание на тёмную**: без выбора пользователя и при любой системной теме — тёмная; светлая — только по явному выбору.

### 3.3 Правила

- Статусные цвета — только как цвет текста/иконки/тонкой рамки или маленькой точки 6 px, **не** как заливка больших площадей. Исключение: тост ошибки — рамка `--danger`.
- Ссылка в тексте — `--fg` с подчёркиванием 1 px (`underline-offset-4`); `--signal` — только для «нового» и счётчиков.
- Выделение текста (`::selection`): фон `--accent`, текст `--accent-fg`.

## 4. Типографика

### 4.1 Гарнитуры (D144: один веб-шрифт ради бюджета LCP)

| Роль    | Шрифт                                                                                             | Где                                                                               |
| ------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Display | **Roboto Condensed 600** (`next/font/google`, latin в предзагрузке, кириллица по `unicode-range`) | заголовки H1–H3, метки, кнопки, навигация, словесный знак                         |
| Text    | системный sans: `system-ui`, Segoe UI, SF Pro, Roboto, Arial                                      | основной текст, поля, описания вакансий                                           |
| Mono    | системный моноширинный: `ui-monospace`, SF Mono, Cascadia Mono, Consolas                          | числа, зарплаты, даты, время, часовые пояса, ID, счётчики — всегда `tabular-nums` |

Подключение — в `src/app/[locale]/layout.tsx` (`display: "optional"`, переменная `--font-display`). Других веб-шрифтов не добавлять без замера LCP: каждые ~50 КБ шрифтов стоят ~300 мс симулированного LCP на главной. Ничего не грузить с CDN в рантайме.

### 4.2 Шкала

| Стиль                        | Шрифт   | Размер (mobile → desktop) | Высота строки | Регистр / разрядка | Вес |
| ---------------------------- | ------- | ------------------------- | ------------- | ------------------ | --- |

| `display-l` (H1 страниц)     | Display | `clamp(32px, 5vw, 56px)`  | 1.0           | UPPER / 0.04em     | 600 |
| `h2`                         | Display | 28 → 32                   | 1.1           | UPPER / 0.06em     | 500 |
| `h3`                         | Display | 20 → 22                   | 1.2           | UPPER / 0.08em     | 500 |
| `label`                      | Display | 12                        | 1.2           | UPPER / 0.16em     | 500 |
| `nav` / `button`             | Display | 14                        | 1             | UPPER / 0.14em     | 500 |
| `body-l`                     | Text    | 18                        | 1.6           | обычный            | 400 |
| `body`                       | Text    | 16                        | 1.6           | обычный            | 400 |

- Длинные заголовки на русском — разрядка не больше `0.06em` у `display-*`, иначе строка разваливается; переносы — `text-wrap: balance`.
- Ширина колонки текста — максимум 68 символов (`max-w-[68ch]`).
- Описание вакансии (пользовательский текст) — всегда `body`, обычный регистр, `white-space: pre-wrap`, без разметки.

## 5. Сетка, отступы, формы

- Базовый шаг — 4 px. Используемые отступы: 4, 8, 12, 16, 24, 32, 48, 64, 96, 128.
- Контейнер: `max-width: 1280px`, поля по бокам 16 px (mobile), 24 px (≥ 768), 48 px (≥ 1280). Узкий контейнер для форм и текста — 720 px.
- Сетка 12 колонок, промежуток 24 px (16 px на mobile).
- Брейкпоинты: `sm 640`, `md 768`, `lg 1024`, `xl 1280`. Проектируем mobile first; на 360 px ничего не должно ехать по горизонтали.
- Вертикальный ритм секций: 64 px (mobile) / 96–128 px (desktop) между крупными блоками.
- Скругление: **0** везде. Исключения: аватар/знак (круг), точка статуса (круг), переключатель-тумблер (капсула).
- Рамки: 1 px `--line`; у полей и контурных кнопок — `--line-strong`; у активного/фокусного — `--accent`.
- Тени: нет. «Подъём» карточки при наведении — смена рамки на `--line-strong` и фона на `--surface-2`.

## 6. Движение и плавность

Характер движения — «инженерный»: быстрое начало, мягкая остановка, без отскоков и пружин. Движение объясняет, что произошло (откуда пришёл элемент, куда ушёл), а не украшает. Всё движение — только `transform` и `opacity` (никаких анимаций `width`, `height`, `top`, `margin` — они дёргают раскладку).

### 6.1 Токены

| Токен     | Длительность | Кривая                     | Применение                                                    |
| --------- | ------------ | -------------------------- | ------------------------------------------------------------- |
| `instant` | 80 ms        | linear                     | нажатие (`:active`), смена иконки                             |
| `fast`    | 120 ms       | `cubic-bezier(.2,0,0,1)`   | hover, смена цвета рамки/текста, сдвиг стрелки                |
| `base`    | 200 ms       | `cubic-bezier(.2,0,0,1)`   | меню, вкладки, тосты, раскрытие фильтров, переход страниц     |
| `slow`    | 400 ms       | `cubic-bezier(.16,1,.3,1)` | появление героя, модальные окна, появление секций             |
| `count`   | 700 ms       | `cubic-bezier(.16,1,.3,1)` | счётчики-телеметрия                                           |
| `stagger` | шаг 60 ms    | —                          | последовательное появление элементов списка, максимум 6 шагов |

Уход элемента всегда быстрее появления (примерно 60 %): появился за 200 — исчезает за 120.

### 6.2 Переходы между страницами

Через React `<ViewTransition>` (встроено в App Router Next 16, браузер без поддержки просто переключает страницу без анимации).

- **Затухание** — для ссылок с типом `nav-fade` (шапка, меню, подвал, вкладки: пропсы `navFade`): перекрёстное затухание контента за `base`. Переход без типа (в том числе первая загрузка — Next гидратирует внутри перехода) не анимируется, иначе страдает LCP (D145). Шапка и подвал не анимируются (`view-transition-name` у шапки — свой, она стоит на месте).
- **Вглубь и назад**: список → карточка (вакансии, отклики, компании, элементы админки) — новая страница въезжает справа на 24 px с затуханием, старая уходит влево на 24 px; «назад» — зеркально. Направление задаётся типом перехода `nav-forward` / `nav-back`.
- **Общий элемент**: название вакансии в карточке списка и H1 на странице вакансии имеют одно имя `job-title-<id>` — при переходе заголовок плавно «перелетает» из карточки в шапку страницы. То же для логотипа компании (`company-logo-<id>`).
- **Внутри одной страницы** (смена вкладки, фильтра, страницы списка) — только перекрёстное затухание области списка, без сдвигов.
- **Индикатор загрузки навигации**: линия 1 px `--accent` под шапкой, растёт слева направо, пока грузится следующая страница; появляется только если ожидание дольше 150 ms (иначе мигает).

### 6.3 Появление на экране

- **Герой главной**: метка (0 ms) → строки заголовка по одной (шаг 80 ms, `translateY(16px)→0` + затухание, строка «выезжает» из-под маски) → поиск (240 ms) → чипы (320 ms). Один раз при загрузке. LCP-элемент (заголовок) виден сразу без анимации непрозрачности — анимируется только сдвиг, иначе Lighthouse считает LCP позже.
- **Секции ниже первого экрана**: `opacity 0→1` + `translateY(8px→0)` за `slow`, когда секция на 15 % вошла в экран; один раз, без повторов при прокрутке назад.
- **Списки карточек**: первые 6 карточек появляются с шагом 60 ms; остальные — сразу.
- **Счётчики-телеметрия** (главная, обзор админки): число «набегает» от 0 до значения за `count`, моноширинный шрифт, табличные цифры — ширина не прыгает.
- **Скелет → данные**: перекрёстное затухание за `base` (Suspense + ViewTransition), без резкой подмены.

### 6.4 Микро-взаимодействия

- Кнопки: инверсия цветов за `fast`; при нажатии `scale(0.98)` за `instant`.
- Ссылки со стрелкой (`→`, `↗`): стрелка сдвигается на 4 px вправо при наведении.
- Карточка вакансии: рамка `--line-strong` и фон `--surface-2` за `fast`; заголовок не двигается.
- Вкладки: подчёркивание 2 px **переезжает** под новую активную вкладку за `base` (а не исчезает и появляется).
- Иконка «Сохранить»: при сохранении контур сменяется заливкой с коротким `scale 1→1.15→1` за 200 ms.
- Переключатель темы: иконка солнце/луна поворачивается на 90° с затуханием за `base`.
- Поля ввода: смена цвета рамки за `fast`; сообщение об ошибке появляется затуханием и сдвигом 4 px сверху.

### 6.5 Наложения

- **Модальное окно**: подложка затухает за `base`; панель — `opacity 0→1` + `scale(0.98)→1` за `base`; закрытие за 120 ms.
- **Мобильное меню**: панель затухает за `base`, пункты меню появляются сверху вниз с шагом 40 ms (`translateY(8px)→0`).
- **Выпадающие меню / фильтры**: затухание + `translateY(-4px)→0` за `base`.
- **Тосты**: въезжают снизу на 8 px с затуханием за `base`, уходят затуханием за 120 ms.

### 6.6 Прокрутка

- Якорные ссылки (оглавление профиля, «к содержимому») — `scroll-behavior: smooth`.
- Шапка при прокрутке страницы больше чем на 24 px получает нижнюю линию и фон `--surface` (переход цвета за `base`); не прячется и не меняет высоту.
- Никакого «прилипания» прокрутки (scroll-snap) на страницах с контентом.

### 6.7 Запреты и доступность

- `@media (prefers-reduced-motion: reduce)` — все длительности 0, переходы страниц выключены, счётчики сразу показывают итог, орбита стоит.
- Никакого видео, параллакса, автокаруселей, отскоков (overshoot), бесконечных анимаций — кроме медленной орбиты героя и пульса скелета.
- Одновременно анимируется не больше 3 независимых групп элементов.
- Анимация не задерживает действие: кнопка, форма, навигация срабатывают сразу, анимация идёт параллельно.
- Кнопка в состоянии загрузки — полоса прогресса 1 px снизу, не спиннер в центре.

## 8. Компоненты (`src/components/ui/*`)

Каждый компонент — один файл, без зависимостей кроме React, `clsx` (если уже есть; иначе простая функция `cn`) и `lucide-react`. Варианты — через props, не через произвольные классы снаружи (разрешён только `className` для внешних отступов). Ниже — обязательный состав и поведение.

### 8.1 Button

- Варианты: `primary` (фон `--accent`, текст `--accent-fg`), `secondary` (прозрачный, рамка `--line-strong`, текст `--fg`), `ghost` (без рамки, подчёркивание при hover), `danger` (контур `--danger`, текст `--danger`).
- Размеры: `md` — высота 44, паддинг по бокам 20; `lg` — высота 52, паддинг 28 (герой); `icon` — 44×44.
- Текст: стиль `button` (капслок, разрядка 0.14em). Иконка справа для переходов (`ArrowRight`), слева — для действий.
- Hover: `primary` — инверсия: фон прозрачный, рамка 1 px и текст `--accent`. `secondary` — рамка `--accent`. `ghost` — подчёркивание. Переход `fast`.
- Disabled: `opacity: .4`, `cursor: not-allowed`, без hover.
- Loading: `aria-busy="true"`, текст остаётся, полоса прогресса 1 px снизу, повторный клик заблокирован.
- Рендер как ссылка: `asChild`-подобный проп `href` → `Link` из `@/i18n/navigation`.

### 8.2 Поля: Input, Textarea, Select, Checkbox, Radio, Switch, Field

- `Field` = `label` (стиль `label`, над полем) + контрол + `help` (`caption`, `--fg-muted`) + `error` (`caption`, `--danger`, `role="alert"`, связан через `aria-describedby`).
- Input/Select/Textarea: высота 44 (textarea — от 120), фон `--surface-2`, рамка `--line-strong`, без скругления; фокус — рамка `--accent` + `outline` 2 px `--accent` со смещением 2 px. Ошибка — рамка `--danger`, `aria-invalid`. Поле на `/chat` — исключение: от одной строки до `min(10rem, 30dvh)`, дальше текст прокручивается внутри (D334).
- Плейсхолдер — `--fg-subtle`, никогда не заменяет label.
- Checkbox/Radio — квадрат/круг 18 px с рамкой `--line-strong`, отмеченный — заливка `--accent`, галочка `--accent-fg`. Зона клика — вся строка с текстом (≥ 44 px).
- Switch — капсула 36×20, для настроек уведомлений.
- Числовые поля (зарплата) — шрифт mono, `inputmode="numeric"`.

### 8.3 Badge / Tag / StatusDot

- Badge: высота 24, паддинг 8, рамка 1 px, текст `label`. Варианты: `neutral` (рамка `--line-strong`), `verified` (`BadgeCheck`, текст `--success`), `trusted` (`ShieldCheck`, `--success`), `imported` (`ArrowUpRight`, `--fg-muted`), `pending` (`--warning`), `danger` (`--danger`), `new` (`--signal`).
- Статусы откликов и вакансий выводятся только через карту `status → вариант+текст` в одном месте (`ui/status-badge.tsx`), не вручную на каждой странице.
- Tag (навык, чип фильтра): высота 32, рамка `--line`, текст `body-s`; выбранный чип — рамка `--accent`; удаляемый — с `X` 16 px и `aria-label`.
- StatusDot: круг 6 px перед текстом (непрочитанное — `--signal`).

### 8.4 Telemetry (Stat)

Блок «метка + значение»: метка — `label` `--fg-muted`, значение — `data` или `data-l`. Используется для зарплаты, часового пояса, формата, опыта, процента совпадения, счётчиков админки. Ряд телеметрии — горизонтальный, разделители — вертикальные линии 1 px `--line`; на mobile — сетка 2×N.

### 8.5 JobCard (карточка в списке)

Анатомия сверху вниз:

1. Ряд меток: категория (`label`), бейджи компании (verified/trusted/imported), «новое» (`new`, если опубликована < 48 ч).
2. Название — `h3`, ссылка на вакансию на всю карточку (одна ссылка, остальные кнопки — поверх с `relative z-10`).
3. Компания — `body-s` `--fg-muted`, ссылка на страницу компании.
4. Ряд телеметрии: зарплата (или «не указана» `--fg-muted`, D164 и D286: `--fg-subtle` на чёрном даёт 4.35:1), формат, часовой пояс/перекрытие, тип занятости.
5. Навыки — до 5 тегов + «+N».
6. Действия справа сверху (desktop) / снизу (mobile): `Bookmark`, `EyeOff`, меню `MoreHorizontal` (скрыть компанию, пожаловаться). Только для вошедших; у гостя — нет.

- Состояния: по умолчанию рамка `--line`, hover — `--line-strong` + `--surface-2`; фокус на ссылке — обводка всей карточки.
- Пропуски данных не оставляют пустых дыр: телеметрия показывает только известные поля.

**Дополнение D204 (маркеры):**

- Ряд меток: до 2 сфер (`Badge` neutral, Web3-сферы первыми), бейдж «Оплата в крипте» (`Badge` tone `new`), если есть условие `crypto-pay`.
- Телеметрия: зарплата всегда первой; уровень (`Stat` «Уровень») — если задан.
- Теги внизу: навыки и условия вместе, не больше 3 + «+N».

### 8.6 Table (админка, отклики работодателя)

Плотная: строка 48, шрифт `body-s`, заголовки `label` `--fg-muted`, разделители строк `--line`, hover строки `--surface-2`. Числа и даты — mono, выравнивание чисел вправо. На mobile таблица превращается в список карточек (не горизонтальный скролл) — кроме админки, где допустим скролл внутри контейнера.

### 8.7 Tabs, Segmented control, Pagination

- Tabs — текст `nav`, активная вкладка — линия 2 px `--accent` снизу. Клавиатура: стрелки.
- Pagination — «Назад / Далее» (у нас курсоры), кнопки `secondary`, без номеров страниц.

### 8.8 Alert, Toast, Banner

- Alert (в потоке страницы): рамка слева 2 px цвета статуса, иконка статуса, текст `body-s`.
- Toast (после действия): правый нижний угол (mobile — снизу на всю ширину), рамка 1 px `--line-strong`, исчезает через 5 с, `role="status"`; ошибки — `role="alert"` и не исчезают сами.
- Banner (системный, на всю ширину под шапкой) — например «Письма пока не отправляются» в админке.

### 8.9 Dialog / ConfirmCard

- Модальное окно: подложка `--overlay`, панель `--surface` с рамкой `--line-strong`, ширина ≤ 560, заголовок `h3`, фокус-ловушка, `Esc` закрывает, возврат фокуса.
- ConfirmCard — карточка подтверждения действия (отклик, сохранение профиля из бота, express interest): что произойдёт, кнопки «Подтвердить» (`primary`) и «Отмена» (`secondary`). Используется и ботом (7A/7B).

### 8.10 EmptyState, Skeleton, ErrorState

- EmptyState: знак-орбита 96 px `--line-strong`, заголовок `h3`, одна строка пояснения, одна кнопка действия.
- Skeleton: прямоугольники `--surface-2` с медленной пульсацией opacity (отключается при reduced motion). Скелет повторяет форму карточки.
- ErrorState (500/ошибка блока): иконка `CircleAlert`, текст, кнопка «Повторить», `x-request-id` мелко mono, чтобы пользователь мог назвать его в поддержке (D48).

### 8.11 Shell: Header, MobileNav, Footer

- Header: высота 64, прозрачный поверх героя главной, на остальных страницах — `--bg` с нижней линией `--line`; при прокрутке на главной становится `--surface` с линией. Слева знак + словесный знак, по центру (≥ 1024) навигация `nav`: «Вакансии», «Компании» (позже), «Для работодателей»; справа: колокольчик со счётчиком (`--signal`, mono), меню аккаунта (выпадающее: профиль, отклики, сохранённые, контакты для работодателя, настройки, админка для админа, выход), переключатели языка и темы. Гость справа: «Войти» (`ghost`), «Регистрация» (`secondary`).
- MobileNav (< 1024): кнопка `Menu` 44×44, полноэкранная панель `--bg`, пункты крупно стилем `h2`, закрытие `X`, фокус-ловушка.
- Активный пункт — линия 2 px снизу.
- Footer: `--bg`, верхняя линия, 4 колонки ссылок (продукт, кандидатам, работодателям, правовое) стилем `body-s` `--fg-muted`, внизу копирайт и переключатель языка, всё mono-цифры для года.
- Ссылка «Перейти к содержимому» (skip link) первой в DOM, видна при фокусе.

## 9. Страницы

Для каждой страницы: композиция, ключевые компоненты, состояния. Все тексты — из `messages`, все страницы en/ru.

### 9.0 Карта разделов, навигация и вкладки

**Принципы навигации**

- Шапка отвечает на вопрос «где я на сайте», вкладки — «какой срез этого раздела я смотрю».
- Каждая вкладка — свой URL (`?tab=` или отдельный путь), её можно открыть по ссылке, обновить и вернуться кнопкой «назад». Без JS вкладки работают как ссылки (компонент `LinkTabs`).
- Активный пункт шапки — белый текст и линия 2 px снизу; активная вкладка — то же внутри страницы. Неактивные — `--fg-muted`.
- Счётчик у пункта/вкладки — моноширинный, `--fg-subtle`; непрочитанное — `--signal`.
- Глубже двух уровней (раздел → вкладка) не уходим. Третий уровень — это уже отдельная страница с «← Назад» над заголовком.
- На телефоне вкладки — горизонтальная лента с прокруткой и затуханием правого края; активная вкладка прокручивается в поле зрения.

**Шапка по ролям** (слева направо; на < 1024 всё уходит в мобильное меню в том же порядке)

| Роль         | Главная навигация                                  | Справа                                                                              |
| ------------ | -------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Гость        | Вакансии · Работодателям                           | язык · тема · «Войти» · «Регистрация»                                               |

### 9.3 Вакансия `/[locale]/jobs/[id]`

- Верх: «← Все вакансии», ряд меток (категория, бейджи), `display-l` название, компания со ссылкой и бейджем, дата публикации mono.
- Ряд телеметрии на всю ширину: зарплата, формат, часовой пояс + требуемое перекрытие, тип занятости, языки.
- Две колонки (≥ 1024): слева описание (`body-l`, max 68ch) и навыки; справа sticky-панель действий: главная кнопка «Откликнуться» (внутренние) или «Откликнуться на сайте источника ↗» (импорт, через `/api/jobs/:id/apply-external`), «Сохранить», «Скрыть», меню «Пожаловаться». ## 10. Состояния и обратная связь (для всех страниц)

- Каждая асинхронная кнопка: loading → успех (toast) / ошибка (toast `role="alert"` + текст из кода ошибки API, если есть в `messages`).

## 12. Производительность

- LCP главной < 2.5 s (медиана 3 прогонов Lighthouse в CI, D41) — бюджет не меняется.
- Шрифты: 3 семейства, только нужные веса (Display 400/500/600, Text 400/500/600, Mono 400/500), сабсеты latin + cyrillic, `display: swap`, preload только Display и Text.
- Изображений нет (кроме логотипов компаний). Декор — инлайн-SVG.
- `lucide-react` — именованные импорты. Никаких UI-фреймворков (MUI, Chakra, shadcn-генераторов) — свои компоненты на Tailwind.
- CLS < 0.1: у скелетов и карточек фиксированные размеры, шрифты с `size-adjust` от `next/font`.

## 13. Реализация в коде

- Токены: `src/app/globals.css` (`:root`, `[data-theme]`, `@theme inline` → утилиты `bg-bg`, `bg-surface`, `text-fg`, `text-fg-muted`, `border-line` и т.д.; шрифты `font-display`, `font-text`, `font-mono`).
- UI-кит: `src/components/ui/` — `button.tsx`, `field.tsx`, `input.tsx`, `select.tsx`, `textarea.tsx`, `checkbox.tsx`, `radio.tsx`, `switch.tsx`, `badge.tsx`, `status-badge.tsx`, `tag.tsx`, `stat.tsx`, `job-card.tsx`, `table.tsx`, `tabs.tsx`, `alert.tsx`, `toast.tsx`, `dialog.tsx`, `confirm-card.tsx`, `empty-state.tsx`, `skeleton.tsx`, `error-state.tsx`, `icon.tsx`, `logo.tsx`, `orbit-backdrop.tsx`, `container.tsx`, `section.tsx`, `index.ts`.
- Витрина компонентов: страница `/[locale]/dev/ui` — все компоненты во всех состояниях, обе темы; отдаёт 404 при `NODE_ENV=production` и в e2e не участвует.
- Клиентские компоненты (`"use client"`) импортируют кит **по файлам**: `import { Button } from "@/components/ui/button"` — иначе индекс `@/components/ui` затягивает в клиентский бандл весь кит (D41a). Серверные компоненты могут импортировать из индекса.
- Страницы используют только `ui/*` и токены. Новые «сырые» цвета и размеры в `className` страниц — повод вернуть работу.
- ESLint-правило (добавляет UI-1): запрет hex-цветов и палитры Tailwind (`*-gray-*`, `*-zinc-*`, `bg-black`, `text-white` и т.п.) в `src/app/**` и `src/components/**`, кроме `globals.css` и `ui/*`.
- **Никаких инлайн-атрибутов `style`.** CSP проекта (`style-src` только с nonce) их блокирует: стиль молча не применяется. Ширины и отступы — классами Tailwind; задержка анимации — атрибут `data-i="0…5"`; имена переходов общих элементов — компонент `Morph` (React `<ViewTransition name>` выставляет имя из JS только на время перехода). Сейчас это нарушают два места — полоса полноты на `/profile` и блок на `/companies/[slug]` (UI-2 переделывает).
- Движение: `Reveal` (появление при прокрутке), `CountUp` (счётчики), `Morph` (общий элемент), `navForward` / `navBack` (пропсы ссылок вглубь/назад), классы `ui-rise` (герой), `ui-stagger`, `ui-fade-up`, `ui-fade-down`. Переход страниц включён один раз в `app/[locale]/template.tsx`.
- Тексты: новые ключи — в `messages` en и ru одновременно (тест паритета уже есть).
- e2e: селекторы по ролям и доступным именам — тексты кнопок не меняем без правки тестов; если меняем, правим тест в той же ветке.

## 14. Разделение работы

Сначала фундамент (без него страницы переделывать нельзя), затем страницы параллельно двумя потоками, у каждого свой набор файлов — пересечений нет.

| Код      | Кто         | Что                                                                                                                                                                                                                                                        | Зависит от | Ветка         | Решения   |
| -------- | ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- | ------------- | --------- |
| **UI-1** | Claude Code | Фундамент: токены и темы (тёмная по умолчанию), шрифты, `lucide-react`, логотип и favicon, весь `src/components/ui/*`, витрина `/dev/ui`, ESLint-запрет сырых цветов, Shell (Header, MobileNav, Footer, skip link), страницы ошибок 404/500                | —          | `claude/ui-1` | D140–D145 |
| **UI-2** | Cursor      | Кандидатская сторона и публичное: главная, каталог `/jobs` с фильтрами и мобильной панелью, вакансия, компания, вход/регистрация/сброс/check-email, онбординг, профиль и редактирование, отклики, сохранённые, уведомления, настройки уведомлений, отписка | UI-1       | `cursor/ui-2` | D155–D159 |
| **UI-3** | Claude Code | Работодатель и админка: `/employer/*`, верификация, `/contacts`, вся `/admin/*` в режиме пульта                                                                                                                                                            | UI-1       | `claude/ui-3` | D146–D148 |
| —        | обе         | D149 — резерв на правки ТЗ дизайна по итогам ревью                                                                                                                                                                                                         |            |               | D149      |

Порядок и правила:

1. UI-1 делается первым и вливается в `master`; Cursor в это время работает над 6A (матчинг, бэкенд), чтобы не простаивать.
2. После вливания UI-1 Cursor берёт UI-2, Claude Code — UI-3, параллельно.
3. В UI-2/UI-3 нельзя менять `src/components/ui/*` и `globals.css`: нужен новый вариант компонента — опиши в отчёте, его добавит владелец UI-1 (Claude Code) отдельным коммитом. Мелкие компоненты, нужные только одной странице, — рядом со страницей или в `src/modules/<module>/ui/`.
4. DoD каждой UI-подфазы: все страницы своего списка переведены на `ui/*`, обе темы, en/ru, mobile 360 px без горизонтального скролла, axe без critical/serious, e2e зелёные, LCP главной в бюджете, скриншоты desktop+mobile в отчёте.
