# ТЗ админ-панели INTGETION JOB LIST

Версия 1 от 2026-10-05. Заменяет разрозненную `/admin/*` (10A–10C, UI-3, 11B, D221–D224) единым продуктом. Делается этапами A1–A7 (раздел 16); до перехода на этап старая `/admin/*` продолжает работать.

Документ — задание для агентов и основателя. Решения, принятые при реализации, записываются в `docs/DECISIONS.md` (номера с D250), отклонения — туда же.

---

## 1. Цели и принципы

1. **Один пульт управления** платформой: состояние сайта и нагрузка, люди и компании, модерация, задачи по расписанию, рассылки, настройки.
2. **Безопасность по умолчанию** — как у крупных сервисов (Stripe, GitHub, Cloudflare): отдельный адрес, обязательный второй фактор, минимальные права, каждое действие в аудите, опасное — с подтверждением, причиной и иногда вторым человеком.
3. **Данные людей — только по делу.** В списках данные маскируются; полные контакты, переписка с ботом и экспорт открываются с указанием причины и попадают в аудит.
4. **Переделываемость.** Разделы — записи в реестре, страницы собраны из общего UI-кита, данные — через сервисы модулей. Сменить дизайн, порядок или набор разделов можно без переписывания логики (раздел 9).
5. **Ничего лишнего в браузере.** Ключи и секреты не покидают сервер; админка не грузит сторонних скриптов.

## 2. Где живёт админка

### 2.1 Адрес

**`admin.intgetion.com`** — отдельный поддомен.

- Тот же Next.js-проект и тот же деплой Vercel (общие модули, миграции, CI). Proxy смотрит на `Host`: запросы к `admin.intgetion.com` идут в маршруты `src/app/(admin)/…`, всё остальное на этом хосте — 404; на основном домене `/admin/*` после переезда — 404.
- Вариант Б, если понадобится полная изоляция: отдельный проект Vercel из того же репозитория со своими env (например, без ключей LLM, но с read-only токеном Vercel API). Переход не требует переписывать код — только сборку.
- Домен добавляется в проект `intgetion-job-list` в Vercel → Domains; DNS у Vercel.

## 3. Вход и сессии

### 3.1 Вход

- Отдельная страница входа на админ-хосте. Только **почта + пароль** (Supabase Auth) **+ второй фактор**. Ссылки на вход (magic link), Telegram и будущие OAuth для админки **запрещены**.
- **Второй фактор обязателен:**
  - основной — **passkey (WebAuthn)**: ключ в телефоне, Touch ID / Windows Hello, YubiKey; не перехватывается фишингом;
  - запасной — **TOTP** (Google Authenticator, 1Password) через Supabase MFA (уровень AAL2);
  - **10 кодов восстановления** выдаются один раз при включении, хранятся только хеши.
- Без настроенного второго фактора админ видит только экран настройки MFA.
- Пароль админа — от 14 символов, не из списка утёкших (проверка по k-anonymity HIBP).

### 3.2 Сессия

| Параметр                         | Значение                                                                   |
| -------------------------------- | -------------------------------------------------------------------------- |
| Бездействие                      | 30 минут → выход                                                           |
| Абсолютный срок                  | 8 часов → повторный вход                                                   |
| Повтор второго фактора (step-up) | перед опасным действием, если с последнего подтверждения прошло > 10 минут |
| Одновременные сессии             | видны в «Безопасность → Мои сессии», любую можно завершить                 |
| Смена роли, пароля, MFA          | завершает все сессии этого админа                                          |

### 3.3 Защита входа

- 5 неудачных попыток за 15 минут → блок на 15 минут (по аккаунту и по IP), письмо владельцу.
- Вход с нового устройства или из новой страны → письмо самому админу и запись в аудит.
- Кнопка **«Завершить все сессии всех админов»** — только у владельца, для инцидента.
- Потеря второго фактора без кодов — восстановление только через другого владельца, с аудитом; одиночный владелец — через Supabase Dashboard по процедуре RUNBOOK.

### 3.4 Хранение

Новая таблица `admin_members`: `user_id`, `role`, `mfa_enrolled_at`, `disabled_at`, `created_by`, `created_at`. Поле `users.platform_role = 'admin'` остаётся для совместимости и выставляется автоматически для любого активного члена команды.

## 5. Аудит и доступ к данным людей

1. **Каждое действие** в админке пишется в `audit_logs`: кто, что, над кем (тип и id), изменения до/после (`diff`), причина, хеш IP, класс устройства, `request_id`, время. Записи только добавляются — ни изменить, ни удалить их из админки нельзя.
2. **Просмотр персональных данных** (полная почта, контакты кандидата, переписка с ботом, экспорт, «смотреть как») требует **причины**: выбор из списка («жалоба №…», «запрос пользователя в поддержку», «проверка мошенничества», «требование закона», «другое» + текст). Без причины кнопка неактивна. Это пишется в аудит отдельным действием `pii.read`.
3. **Маскирование в списках**: почта `a***@gmail.com`, телефон `+7 *** ***-12-34`; полное значение — только на карточке по кнопке «Показать» (п. 2).
4. **Экспорт CSV** — только владелец и админ, не больше 10 000 строк, без контактов кандидатов; в файл добавляется строка «Выгрузил: … , когда: …»; действие в аудите.
5. **Срок хранения** аудита админ-действий — 2 года (у общих событий аудита остаётся 365 дней, раздел 17 ТЗ). Это новое решение — записать при реализации.
6. **Еженедельная сводка владельцу** (письмо и Telegram): сколько входов в админку, кто смотрел персональные данные и сколько раз, опасные действия.
7. **Пользователь видит** в экспорте своих данных (`GET /api/me/export`), что его профиль просматривала поддержка (дата и цель, без имени сотрудника).

## 6. Разделы и экраны

Общий каркас — раздел 8. Ниже для каждого раздела: что показывает, какие кнопки, кто может.

### 6.1 Обзор (главная)

- **Плитки**: посетители сегодня/за 7 дней, регистрации (кандидаты/работодатели), новые вакансии, отклики, взаимный интерес — с изменением к прошлому периоду.

### 6.3 Задачи по расписанию (cron)

**Проблема сейчас:** расписания задач зашиты в `vercel.json` — без нового деплоя их не включить, не выключить и не запустить вручную.

**Как будет:**

1. **Реестр задач в коде** — `src/scheduler/registry.ts`: ключ, обработчик, описание, расписание по умолчанию, таймаут, схема параметров (zod), признак «можно запускать вручную». Все 11 текущих задач (истечение вакансий, курсы валют, импорт, trusted, уведомления, истечение вакансий-напоминание, хранение, матчинг, дайджест, оповещения, Telegram) переезжают в реестр.
2. **Таблица `scheduled_jobs`**: `key`, `instance` (одна задача может быть запущена в нескольких экземплярах с разными параметрами), `enabled`, `schedule` (cron-выражение), `params` (jsonb), `last_run_at`, `next_run_at`, `locked_until`, `updated_by`.
3. **Таблица `job_runs`**: `id`, `key`, `instance`, `trigger` (`schedule` / `manual`), `actor`, `started_at`, `finished_at`, `status` (`ok` / `failed` / `timeout` / `skipped`), `result` (jsonb — счётчики, которые вернула задача), `error`.
4. **Один cron Vercel** — `/api/cron/tick` каждую минуту: берёт задачи, у которых наступило `next_run_at` и `enabled`, захватывает (`for update skip locked` + `locked_until`), выполняет с таймаутом, пишет `job_runs`, считает следующее время. В `vercel.json` остаётся только tick (и на время перехода — старые маршруты, выключенные флагом).

**Экран «Задачи»**: таблица — задача, описание, расписание человеческим языком («каждый час в :05»), вкл/выкл, последний запуск (время, статус, длительность), следующий запуск, ошибки за 24 ч.

**Кнопки**:

- **Вкл/Выкл** — переключатель, с причиной; выключение критичных (уведомления, хранение данных) — с предупреждением.
- **Изменить расписание** — поле cron-выражения с подсказкой и предпросмотром «следующие 5 запусков»; не чаще раза в минуту; часовой пояс UTC с подписью местного времени.
- **Параметры** — форма по схеме задачи (например, размер пачки, порог, окно).
- **Запустить сейчас** — с подтверждением; повторно, пока идёт, нельзя.
- **Добавить экземпляр** — «добавить задачу» = выбрать обработчик из реестра и задать своё расписание и параметры (например, второй дайджест для другого часового окна). Написать новую задачу из админки нельзя — только из кода, это сознательное ограничение безопасности.
- **История** — список `job_runs` с фильтром по статусу и графиком длительности; результат и ошибка раскрываются.
- Все изменения — в аудит; права `jobs_scheduler.*` (раздел 4).

### 6.4 Пользователи

**Список**: id (коротко), имя, роль (кандидат/работодатель/оба), статус (активен/приостановлен/заблокирован/удалён), способы входа (почта/Telegram), язык, полнота профиля, дата регистрации, последняя активность, отметки (жалобы, риск). Почта — маскированно.

**Фильтры**: статус, роль, способ входа, язык, дата регистрации, активность, полнота, «есть жалобы», «подозрительный» (риск-сигналы 18.1). **Поиск**: по id, точной почте (ищет по хешу, не показывая список почт), Telegram-нику, имени.

**Массовые действия**: только «добавить заметку» и «выгрузить» (с правом). Массовая блокировка — запрещена (только по одному, с причиной).

| Уведомления         | настройки каналов, последние 50 уведомлений, ошибки доставки                                     | —                                                                                                        |
| Бот                 | диалоги — только по кнопке с причиной (право `users.bot.read`)                                   | —                                                                                                        |
| Аудит               | все действия админов над этим пользователем и его заметные действия                              | —                                                                                                        |
| Заметки             | внутренние заметки команды (видны только админам)                                                | Добавить заметку                                                                                         |

**Действия подробно**:

- **Приостановить**: причина (список + текст), срок (1 день / 7 / 30 / до снятия), уведомить пользователя (письмо с причиной по шаблону; по умолчанию включено). Приостановленный не может войти, его вакансии на паузе, профиль скрыт. Снимается кнопкой или по сроку.
- **Заблокировать навсегда**: всё, что при приостановке, плюс запрет повторной регистрации — хеши почты и Telegram-id в `blocklist`. Подтверждение вводом почты пользователя + step-up (3.2).
- **Удалить аккаунт**: процедура D28 (анонимизация); подтверждение вводом почты; для админа или владельца компании с вакансиями — второй человек одобряет.
- **Выйти из всех сессий**: Supabase Admin API (logout всех refresh-токенов).
- **Сбросить пароль**: письмо со ссылкой сброса; пароль админ не видит и не задаёт.
- **Смотреть как пользователь** (impersonation, только просмотр): причина, срок 15 минут, красная полоса «Вы смотрите как …» на каждой странице, любые изменения запрещены на сервере, запись в аудит начала и конца; в экспорте данных пользователя видно (5.7).
- **Выгрузить данные пользователя** (по его запросу, GDPR): тот же JSON, что `GET /api/me/export`, с причиной.

### 6.5 Компании

**Список**: название, slug, статус верификации, trusted, вакансий (опубликованные/всего), подписчиков (D239), жалоб, дата. Фильтры: статус, trusted, есть жалобы, без вакансий; поиск по названию, slug, домену.

**Карточка**: данные компании и логотип, участники и роли, вакансии, история верификации (почта/DNS/реквизиты, 10B), риск-флаги, жалобы, подписчики (число), аудит, заметки.

**Кнопки**: Подтвердить, Отклонить верификацию (причина), Отметить trusted / снять, Приостановить компанию (вакансии на паузу, причина, уведомить владельца), Восстановить, Изменить название/описание (причина), Удалить логотип, Передать владение (выбор участника, второй человек одобряет).

### 6.6 Вакансии

**Список**: название, компания, источник (своя/импорт), статус, риск-балл, дата публикации и истечения, просмотры (D232), отклики. Фильтры: статус, источник, компания, риск, категория, «с жалобами»; поиск по названию.

**Кнопки на карточке**: Открыть на сайте, Снять с публикации (причина, уведомить работодателя), Вернуть, Продлить срок, Изменить категорию/навыки (причина), Пометить как мошенничество (снять + жалоба-основание + риск компании).

### 6.7 Модерация

Очередь вакансий и компаний (D130–D134): вкладки «Вакансии (N) · Компании (N)», сортировка по возрасту, просроченные > 24 ч выделены, риск-сигналы с объяснением.

Кнопки на элементе: **Одобрить**, **Отклонить** (причина из списка + текст, уведомление автору), **Запросить правки** (текст для автора), **Взять себе** (закрепить за модератором на 30 минут, чтобы двое не делали одно). Горячие клавиши: `A` — одобрить, `R` — отклонить, `J/K` — следующий/предыдущий.

### 6.8 Жалобы

Вкладки «Открытые · Подтверждённые · Отклонённые»; группировка жалоб на один объект; авто-пауза (10A) видна. Кнопки: **Подтвердить** (выбрать действие: снять вакансию / приостановить компанию / приостановить пользователя), **Отклонить**, **Ответить автору** (шаблон).

### 6.9 Импорт

Источники (8A/8B): вкл/выкл, последние прогоны (найдено, добавлено, дубли, отклонено), ошибки, условия использования источника (`republish_allowed`). Кнопки: Запустить сейчас (через 6.3), Выключить источник, Удалить все вакансии источника (второй человек).

### 6.10 Навыки и справочники

Предложенные навыки (D-2A): **Сопоставить** с существующим, **Создать** новый, **Отклонить**; редактирование алиасов; сферы и категории (MARKERS.md) — только чтение, изменения через код.

### 6.11 Рассылки (почта и Telegram)

**Виды**:

| Вид                                                                                                  | Кому можно                                                                                   | Отписка                                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Сервисное сообщение** (изменение условий, инцидент безопасности, важная перемена в работе сервиса) | всем активным                                                                                | нельзя отписаться; не чаще раза в месяц; без рекламы                                                                                                                           |
| **Новости и предложения** (маркетинг)                                                                | почта — только с `marketing_opt_in = true`; Telegram — только с включённым каналом «Новости» | ссылка «Отписаться» в каждом письме и сообщении, заголовок `List-Unsubscribe` + `List-Unsubscribe-Post` (one-click, RFC 8058 — требование Gmail и Yahoo для массовых рассылок) |

**Аудитория** (конструктор с предпросмотром числа получателей): роль, язык, дата регистрации, активность за N дней, полнота профиля ≥ X, способ входа, есть Telegram, часовой пояс/страна, работодатели верифицированных компаний, исключить приостановленных (всегда). Сохранённые сегменты.

**Содержимое**: тема, текст (Markdown, очищается allowlist-ом), кнопка (текст + ссылка только на домен платформы), отдельно для en и ru; для Telegram — короткий текст ≤ 4000 символов без разметки. Предпросмотр письма в оболочке `siteEmailHtml` и сообщения Telegram.

**Шаги и кнопки**:

1. **Черновик** — Сохранить.
2. **Отправить тест себе** — почта и Telegram самому отправителю.
3. **Запросить одобрение** — обязательно для маркетинга и для любой рассылки больше 500 получателей; одобряет другой человек с правом `broadcast.approve`, видит итоговый текст и число получателей.
4. **Запланировать** (дата/время с часовым поясом получателя или общим) или **Отправить сейчас**.
5. **Прогресс**: отправлено / доставлено / ошибки / пропущено (нет согласия, заглушка Telegram-адреса, отписан) / отписались; кнопка **Остановить**.
6. **Архив** с текстом, аудиторией, статистикой и тем, кто одобрил.

**Техника**: очередь `broadcast_deliveries` (получатель, канал, статус, ошибка); отправка задачей из 6.3 пачками — почта через Resend batch (до 100 писем за вызов, в пределах лимита тарифа), Telegram — не больше 25 сообщений в секунду суммарно и 1 в секунду на человека; повтор при временной ошибке до 3 раз; idempotency-ключ на получателя. Маркетинговые письма — с отдельного адреса и поддомена (`news.intgetion.com`), чтобы жалобы на рассылку не портили репутацию писем входа и уведомлений; SPF, DKIM, DMARC — для обоих. Записи доставки хранятся 90 дней.

### 6.12 Аналитика

### 6.13 Настройки и флаги

- **Настройки прода** (D229) — только чтение, что задано и в каком режиме.
- **Флаги функций** (`feature_flags`: ключ, вкл/выкл, процент, комментарий, кто менял): регистрация открыта/закрыта, вход через Telegram, бот, импорт, рассылки, новые разделы. Изменение — с причиной, право `flags.manage`.

- **Экстренные кнопки** (только владелец, step-up, причина):
  - **Режим только чтения**: сайт работает на просмотр, регистрации, отклики и публикации временно закрыты с понятным сообщением;

  - **Остановить все рассылки и задачи**;
  - **Завершить все сессии админов**.

### 6.14 Команда (администраторы)

Список членов команды, роль, MFA (есть/нет), последний вход, статус. Кнопки: **Пригласить** (почта + роль; приглашение действует 48 ч; вход только после настройки MFA), **Изменить роль**, **Отключить**, **Сбросить MFA** (второй владелец). Нельзя отключить последнего владельца.

### 6.15 Аудит

### 6.16 Безопасность

## 8. Общий интерфейс

- **Каркас**: слева навигация 220 px (иконка + название + счётчик), сверху — глобальный поиск, переключатель темы, меню профиля (мои сессии, выход). Красная полоса сверху в режиме «смотреть как» и в режиме только чтения.
- **Глобальный поиск** `Ctrl+K`: по id, почте (точное совпадение), Telegram-нику, названию компании, slug, названию вакансии → переход к карточке.
- **Таблицы**: сортировка, фильтры и сортировка в URL (ссылку можно отправить коллеге), курсорная пагинация, выбор столбцов (запоминается), пустые и ошибочные состояния, плотный режим.
- **Опасные действия**: `danger`-кнопка → карточка подтверждения: что произойдёт, кого затронет, поле причины, для необратимого — ввод названия/почты; step-up при необходимости; итог — toast и запись в аудит.
- **Второй человек** (4-eyes): действие создаёт запрос; второй с правом видит его на «Обзоре» и в разделе, одобряет или отклоняет; запрос живёт 24 часа.
- **Телефон**: все разделы доступны для чтения; опасные действия — только на компьютере.
- Язык интерфейса — en/ru, как на сайте.

## 9. Переделываемость

1. **Реестр разделов** `src/admin/registry.ts`: ключ, путь, название (ключ перевода), иконка, право, источник счётчика, флаг. Навигация, поиск по разделам и проверка прав строятся из реестра — новый раздел = одна запись + страница.
2. **Страницы без SQL**: данные только через `service/index.ts` модулей (правило ESLint проекта); у админки свой модуль `src/modules/admin-console` для запросов, которых нет в модулях.
3. **UI** — только компоненты `src/components/ui/*` и `src/components/admin/*`; цвета и размеры — токены `DESIGN.md`. Редизайн = замена компонентов и токенов без правки логики.
4. **Действия** — серверные обработчики `/api/admin/*` с единым обёрточным слоем: проверка права → step-up при необходимости → причина → выполнение → аудит. Новое действие подключается одной функцией.
5. **Тексты** — ключи `admin.*` в `src/messages/{en,ru}.json`.

## 10. Безопасность — сводный список (как у крупных сервисов)

- Отдельный хост, IP-список или Zero Trust, noindex (2.2).
- Обязательный phishing-resistant второй фактор (passkey), запасной TOTP, коды восстановления (3.1).
- Короткие сессии, step-up, отзыв сессий, уведомления о новых входах (3.2–3.3).
- Минимальные права, проверка на сервере, 404 на чужое (4).
- Аудит всего, причина для персональных данных, маскирование, неизменяемость, сводка владельцу (5).
- Второй человек для необратимого и массового (6.4, 6.11, 6.14, 8).
- CSRF по Origin, строгий CSP, `SameSite=Strict`, `__Host-` куки, без сторонних скриптов.
- Лимиты запросов на каждое действие админа (например, не больше 30 просмотров персональных данных в час на человека — превышение = алерт владельцу).
- Секреты — только в env, никогда не показываются; read-only токены для внешних API (Vercel, Sentry).
- Ежегодная внешняя проверка (pentest) админки и после крупных изменений; чек-лист OWASP ASVS уровня 2.
- RUNBOOK: «компрометация аккаунта админа» — завершить все сессии, сбросить MFA, проверить аудит, ротация ключей.
