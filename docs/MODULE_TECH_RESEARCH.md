# Готовые технологии для действующих модулей

Исследование 2026-11-03, продолжение [общего обзора](WEB3_AI_TECH_RESEARCH.md). Границы D600 сохраняются: предложения, без установки и реализации. Ниже выбраны компоненты под конкретные сценарии; готовность к production и совместимость точных версий ещё требуют пилота.

## Короткий выбор

Наиболее предметные кандидаты: **ics для событий**, **jsdiff для читаемых изменений условий**, **ESCO для расширения словаря навыков**, **TanStack Table для сложных кабинетов**. Для остальных решений выгода пока слабее стоимости адаптации. Это технический отбор, а не измеренный пользовательский спрос.

## Что уже решено своим кодом

- **Версии UGC:** `src/modules/ugc/__tests__/versions.test.ts` проверяет сравнение полей и сохранение исходного состояния. jsdiff полезен только если пользователю мало существующего «до/после».
- **Просмотр видео:** `src/modules/ugc/service/embed.ts` создаёт iframe URL только для разрешённых платформ и идентификаторов. Общий плеер не должен расширить доступ произвольным URL.
- **Импорт событий:** уже есть адаптер `confs-tech.ts`, использующий `tech-conferences/conference-data` с атрибуцией. Этот репозиторий уже применяется; его нельзя выдавать за новое подключение.
- **Навыки:** aliases, нормализация, suggestions и `pg_trgm` уже реализованы. ESCO может улучшить содержимое словаря; не заменяет текущие hard-фильтры, объяснения matching или права доступа.
- **Формы и схемы:** Zod и react-hook-form уже установлены. AJV полезен при конкретном внешнем JSON Schema-контракте, но сейчас добавлять параллельную валидацию не предлагается.
- **Аккаунт:** Supabase Auth, общий пользователь и членство в компаниях — существующая основа. Новый репозиторий авторизации не решает открытый выбор провайдера верификации личности и не должен создавать второй аккаунт.

## Решения, которые пока не подходят

**Загрузка файлов — [Uppy](https://github.com/transloadit/uppy).** Решает выбор и загрузку файлов; resumable upload требует соответствующего транспортного плагина и сервера. Но D573 в ТЗ 48 прямо выбирает ссылки без хранения видео. Поэтому Uppy, транскодирование и файловый C2PA не входят в текущий UGC. Для будущего CV upload оценивать отдельно после разрешения V2, выбора приватного хранилища и правил обработки. Лицензию точного набора пакетов и совместимость с выбранным хранилищем здесь не проверяли.

**Запись пользовательских сессий — [rrweb](https://github.com/rrweb-io/rrweb).** Может помочь воспроизводить интерфейсные ошибки, но запись DOM на страницах профиля, чата и заказа создаёт новый поток чувствительных данных. Пока использовать существующие коды ошибок, request ID, безопасные события и тестовые воспроизведения. Само наличие маскировки не доказывает соблюдение правил приватности; для внедрения нужны отдельная модель данных и проверка всех исключённых поверхностей. Лицензия выбранного релиза не проверялась, кандидат не выбран.

**Полный ATS, CRM или marketplace из чужого репозитория.** Это перенос схемы аккаунтов, прав, платежей и жизненного цикла, а не подключение одного модуля. Без отдельного архитектурного исследования и лицензии такой перенос не рекомендуется. Особенно не заменять Supabase/Drizzle чужой системой пользователей только ради красивого кабинета.

## Как выбрать один пилот

1. **Быстрая самостоятельная польза — календарный экспорт.** Проверить, есть ли точные даты/время в текущих источниках и хотят ли пользователи сохранять события. Приёмка: импорт в два календаря, RU/EN, DST и all-day; никаких ложных обещаний регистрации или автоматического обновления.
2. **Ясность условий — jsdiff на существующей истории UGC.** Приёмка: длинный текст, удаление, пустая строка, несколько языков, чужая версия, просмотр на телефоне. Сравнить с текущим экраном: действительно ли быстрее видно изменение.
3. **Качество поиска — ESCO как редакторский эксперимент.** Взять реальные обезличенные запросы с нулевой выдачей; сравнить до/после на ручной разметке, измерить ложные соответствия и время редактора. Не повышать score по непроверенному внешнему словарю.
4. **Удобство работы команды — TanStack Table.** Выбрать одну наблюдаемую проблему кабинета; проверить скорость нахождения заявки, клавиатуру, пагинацию и права пользователя с двумя компаниями.

Не начинать все четыре одновременно. OPEN QUESTION: какой сценарий сейчас чаще мешает пользователям — поиск по навыкам, чтение правок, работа со списками или сохранение событий. Пока метрик нет, приоритет по ожидаемому эффекту условный; самый ограниченный технически пилот — экспорт календаря.

## Метод и пределы

Проверены текущие документы и указанные исходники проекта; официальные репозитории и документация — 2026-11-03. Для ics и jsdiff прочитаны LICENSE; для остальных лицензии указаны там, где они явно заявлены репозиторием, без проверки всех транзитивных зависимостей. Условия ESCO API и данных разделены. Платные сервисы не вызывались, пакеты не устанавливались, демонстрации не запускались. Совместимость и продуктовый эффект — предмет будущих тестов.

Навыки: graphify (прочитан ранее, граф и CLI отсутствуют, прямое чтение), verification-before-completion. REA не нужен: использованы открытые источники. Никакая библиотека из обзора не считается автоматически одобренной к внедрению.
