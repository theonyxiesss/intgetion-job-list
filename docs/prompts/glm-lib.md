## Что сделать

### `src/lib/money.ts` (10.4, D4, D5, D19)

- Только `bigint` в минорных единицах; `number` и float для сумм запрещены (D19). Валюта — ISO 4217 `char(3)`, период `hour | month | year`, база `gross | net`.
- DTO денег по разделу 6: `{ amountMinor: string, currency, period, basis }` + разбор обратно с проверкой (строка из цифр, валюта из 3 заглавных букв). Ошибочный ввод — исключение, не тихий ноль.
- Приведение периода: year → month `/12` с банковским округлением в минорных единицах; hour ни во что не приводится.
- Курсы: функция получает курсы снаружи (`{ currency, rateToUsd: string /* numeric(18,8) */, asOf: Date }`), сама в БД не ходит. Курс старше 7 дней от переданного `now` — как отсутствующий. Арифметика курсов — BigInt с фиксированной точкой (8 знаков), без float.
- Сравнимость: разные периоды после приведения, gross ≠ net, нет свежего курса → результат «несравнимо» (нейтрально, D4/D5) с причиной. Возвращай размеченный результат, например `{ comparable: false, reason: "basis" | "period" | "fx_missing" | "fx_stale" }` или `{ comparable: true, jobMonthlyMinor, candMonthlyMinor }` в одной валюте.
- Скор зарплаты по 10.4.4: `J = job.salary_max ?? job.salary_min`, `C = cand.salary_min`; `J ≥ C` → 1; иначе `r = J/C`, `s = max(0, (r − 0.7)/0.3)`. Скор — число 0..1 (это не деньги), но вычисляй отношение из BigInt без потери точности. `C = 0` и отсутствие `J` — явные случаи.

### `src/lib/tz.ts` (10.6, D6)

- Только IANA-зоны; проверка через `Intl` (`isValidTimeZone`). Фиксированные смещения запрещены.
- `localToUtc(date, "HH:MM", timeZone)` — подбор смещения на конкретную дату через `Intl.DateTimeFormat(…, { timeZone })`, корректно в дни перехода DST (несуществующее и повторяющееся локальное время — опиши выбранное правило в D65).
- `workHoursOverlap({ candidate: { timeZone, start, end, workDays }, job: { timeZone, start?, end? }, from: Date, days = 14 })` по псевдокоду 10.6: дни по календарю UTC, пропуск дней не из `workDays` (ISO weekday, в зоне кандидата), окна вакансии по умолчанию 09:00–18:00, окна через полночь (end < start), результат — среднее пересечение в минутах на рабочий день и разбивка по дням для отладки.
