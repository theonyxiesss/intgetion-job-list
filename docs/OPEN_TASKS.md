## Phone Mini App — кнопка меню бота

- **Статус: НЕ ЗАКРЫТО** (подтверждено основателем 2026-10-07 после выкладки D324).
- **Симптом:** Telegram Desktop / Web по кнопке меню бота входит; **телефон по той же кнопке — нет** (гость / без сессии).
- **Уже пробовали и выкладывали:**
  - D320 — Lax vs Partitioned на телефоне
  - D321 — парсер `#/path?tgWebAppData`, осторожный `framed`
  - D322 — bounce `/` без HTTP 307, `sessionStorage` hash, `/tg.html`
  - D324 — официальный `telegram-web-app.js`, CSP `https://telegram.org`, stash raw `initData`, ожидание bridge
- **Логи после D324 (окно ~2 ч вокруг ретеста):** запросов к `/api/auth/telegram/miniapp` в runtime-логах Vercel по-прежнему не видно — клиент на телефоне, скорее всего, так и не отправляет подписанную строку (или запросы не попадают в этот срез логов).
- **Решение по процессу:** auto-sign-in через Mini App на телефоне **больше не крутить** без новых фактов (скрин/платформа iOS|Android, точный URL BotFather, есть ли вызов miniapp в логах). Рабочий обход для телефона сейчас: вход через бота (`login_*` / кнопка «Войти» в чате), не через меню Mini App.
- **Следующая отдельная задача (когда брать):** либо диагностика с телефоном в руках (что в `location.hash` / `Telegram.WebApp.initData` в webview), либо явная кнопка «Войти через Telegram» внутри Mini App на телефоне вместо тихого auto-sign-in.

- **Статус: НЕ ЗАКРЫТО / ОТЛОЖЕНО** (основатель 2026-10-07: «пока не работает хорошо — отложим, но запиши»).

## PLANNED (решение основателя 2026-10-07, не начинать без команды)

### Языки сайта: адреса без `/en` + новые языки

Решено: не определять язык по IP/провайдеру (VPN, экспаты, Googlebot с US-IP, риск cloaking) и не уходить в «только английский + Google Переводчик» (теряется русский SEO, письма/бот/ошибки не переводятся).

1. **Шаг 1 — адреса. СДЕЛАНО локально (D335, ветка `feat/home-job-feed`, не на проде).** Английский на корне без префикса (`/jobs`), остальные языки с префиксом (`/ru/...`): next-intl `localePrefix: "as-needed"`. Первый заход на `/` — язык из `Accept-Language`, дальше выбор в куке + переключатель. Нужно: 301 со всех `/en/...`, sitemap, hreflang/canonical, ссылки в письмах (`render.ts`, `email-html.ts`, Supabase-шаблоны D330), Telegram-ссылки, e2e. Ожидать несколько недель переиндексации.
2. **Шаг 2 — новые языки, по одному и по данным** (Search Console, `/admin/metrics`: страны и языки браузера; порог ~10% трафика):
   - сначала испанский (`es`) и бразильский португальский (`pt-BR`) — крупнейшие рынки удалённой работы;
   - потом немецкий (`de`) и французский (`fr`);
   - итальянский (`it`) — последним.
3. **На каждый язык:** перевод `src/messages/*.json` (~1700 строк, машинный + вычитка носителем), письма и уведомления, ответы бота, юридические тексты (условия/политика — перевод человеком, GDPR для de/fr/it), проверка вёрстки на длинных строках (немецкий).
4. **Ограничение:** вакансии остаются на языке работодателя — переводится только интерфейс. Подумать, как это показать пользователю (метка языка вакансии / требование английского).
