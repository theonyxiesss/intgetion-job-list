# Планы после MVP (D214)

Запись решений основателя от 2026-10-04. Это план, не задание: каждая часть станет подфазой со своими решениями, когда до неё дойдёт очередь. Порядок — в конце.

## P-API. Платный API платформы

**Что:** публичный REST API для партнёров (агрегаторы, HR-сервисы, Telegram-каналы, исследователи) по ключу и тарифу.

- Ключи в кабинете (`/settings/api` или `/employer/api`): создать, отозвать, видеть последний вызов. В БД — только хеш ключа (как `bot_session`, D172), сам ключ показывается один раз.
- Тарифы: бесплатный (мало запросов в сутки, только поиск), платные — больше лимит, вебхуки о новых вакансиях, выгрузка по фильтрам. Лимиты — через `rate_limit_counters` по ключу (D26). Оплата — Stripe или крипто-процессинг, решение основателя.
- Версия в пути: `/api/v1/public/jobs`, `/api/v1/public/jobs/:id`, `/api/v1/public/companies/:slug`, `/api/v1/public/taxonomy`. Публичный DTO 4A, курсорная пагинация (раздел 6), OpenAPI-описание и страница документации.
- **Ограничение по данным:** через платный API отдаются только **собственные вакансии** платформы (`source = internal`). Импортированные принадлежат источникам, а их условия запрещают перепродажу и передачу третьим лицам (Remotive прямо, CryptoJobsList и We Work Remotely — по смыслу ToS). Импорт отдавать только со ссылкой на источник и только если источник это разрешает (`import_sources.republish_allowed`, уже есть в схеме).
- Контакты кандидатов и любые персональные данные через API не отдаются никогда (D3, 5.3).
- Работодателю — отдельный API своих вакансий и откликов (создать/обновить вакансию, получить отклики по своим вакансиям) — это интеграция с ATS, V3 по разделу 21.

## P-MCP. MCP-сервер платформы

**Что:** сервер Model Context Protocol, чтобы ИИ-ассистенты (Claude, ChatGPT, Cursor и др.) могли искать вакансии и работать с аккаунтом пользователя.

- Транспорт — Streamable HTTP на `/mcp`, авторизация — OAuth 2.1 (тот же аккаунт Supabase) или ключ платного API.
- Инструменты: `search_jobs`, `get_job`, `get_company`, `list_categories`; для вошедшего — `get_my_matches`, `save_job`, `get_my_applications`; действия с записью (`apply_to_job`) — только с подтверждением пользователя в интерфейсе ассистента, как у нашего бота (D173).
- Переиспользует слой инструментов бота (`src/modules/bot/service/tools.ts`): одни и те же проверки прав и лимиты.
- Те же ограничения по данным, что у API: импорт — только со ссылкой и там, где разрешено; контакты — никогда.
- Лимиты и тарифы — общие с платным API.

## P-COOKIES. Персонализация с согласия

**Что:** если пользователь нажал «Принять все» (D201), сайт запоминает больше, чтобы лучше подстраиваться.

- Разделить согласие на категории (как у Remote3): необходимые (всегда), **предпочтения** (тема, язык, последние фильтры каталога, свёрнутые блоки), **аналитика** (просмотры, клики, воронка, без рекламы), маркетинг — не собираем. Баннер — «Принять все / Только необходимые / Настроить», настройки — в `/settings/privacy` (уже есть блок, D201).
- Что даст персонализацию **без куки и без согласия** — используем сразу, это не слежка: часовой пояс из браузера (`Intl.DateTimeFormat().resolvedOptions().timeZone`) — уже применяется в профиле; язык браузера (`Accept-Language`) — для выбора локали; тип устройства — для раскладки. Версию браузера для персонализации не храним — она нужна только в логах ошибок (Sentry, 11B) без привязки к человеку.
- С согласием «предпочтения»: помнить фильтры каталога и последние просмотренные вакансии гостя, предложить их в подборе после регистрации.
- С согласием «аналитика»: собственная аналитика без сторонних трекеров (события в своей БД или self-hosted Plausible/Umami), обезличенно, срок хранения — по разделу 17. Метрики 10.8 (CTR рекомендаций и т.п.) считаются из неё.
- Всё через `consentAllows` (`src/lib/consent.ts`): без согласия — не пишем. Отзыв согласия удаляет собранное.

## P-MOBILE. Мобильная версия

Уже есть: адаптивная вёрстка, 360 px без горизонтальной прокрутки в e2e, мобильное меню, панель фильтров, прилипающая панель действий вакансии.

Дальше:

- e2e для всех основных страниц на 360 и 390 px; Lighthouse mobile для `/jobs/[id]`, `/matches`, `/chat`, не только главной.
- PWA: манифест, иконки, установка на экран, офлайн-страница; push-уведомления о новых совпадениях (с согласием) — вместе с 9B.
- Удобство: большие зоны нажатия (≥ 44 px уже в DESIGN 11), нижняя навигация для кандидата на телефоне (Вакансии · Подходящие · Отклики · Чат · Профиль), свайп «не подходит» в подборе.
- Чат бота — полноэкранный на телефоне, клавиатура не перекрывает поле ввода.

## P-SCRAPE. Защита от парсинга

**Цель:** данные платформы забирают через платный API, а не скрейпингом сайта.

**Честно о пределах:** публичные страницы вакансий должны оставаться доступными людям и поисковикам (иначе пропадёт трафик и Google, D210–D211), поэтому полностью закрыть их невозможно — можно сделать массовый парсинг дорогим и бессмысленным и закрыть его юридически.

- **Лимиты:** глобальный лимит по IP уже есть (300 запросов/мин, раздел 6) — ужесточить для страниц каталога и вакансий для неавторизованных (например, 60/мин), отдельные лимиты для `GET /api/jobs` без ключа. Подозрительным — CAPTCHA-вызов через Cloudflare Turnstile или аналог, а не бан.
- **Боты:** Vercel Firewall / Cloudflare Bot Management — пропускать проверенных поисковых ботов (Googlebot, Bingbot по обратному DNS), блокировать известных скрейперов; в `robots.txt` — запрет для SEO-скрейперов (AhrefsBot, SemrushBot и т.п., как у CryptoJobsList).
- **Без лёгкой выгрузки:** внутренний `/api/jobs` — только для нашего фронтенда (проверка `Origin`, короткоживущий токен страницы), большие `limit` запрещены (≤ 50 уже, раздел 6); никаких публичных списков с тысячами записей; RSS — последние 50, без описаний.
- **Признаки:** ловушки (скрытые ссылки, которые человек не видит), слежение за аномалиями (много страниц вакансий подряд без JS, без куки, с одного ASN) → алерт 18.1.
- **Юридически:** условия использования запрещают автоматический сбор вне API; страница API с тарифами — легальная альтернатива.
- Не мешать людям: никаких CAPTCHA для обычных посетителей, никаких блокировок по стране.

## P-MODEL. Модель для бота

- Сейчас (D213): OpenRouter, бесплатная `qwen/qwen3.8-27b:free` — для разработки и показа.
- Для запуска — быстрая дешёвая модель («flash»-класса) для чата и поиска и более сильная — для разбора профиля из диалога (extract), где ошибки дороже. Выбор — после evals 7B: модель обязана пройти golden (20) и adversarial (15) наборы с порогами 19.3. Цена — в `LLM_PRICES_MICRO_USD`, дневной бюджет — `LLM_DAILY_BUDGET_USD`.

## P-LANG. Ещё языки

Сейчас на сайте английский и русский. Язык выбирается сам: кука `NEXT_LOCALE`, иначе язык браузера, иначе английский. Кнопок EN/RU на странице нет (D216). Адреса `/en` и `/ru` остаются.

Дальше, отдельной подфазой, добавить ещё два языка из самых частых для удалённой работы: испанский и португальский. Набор можно сменить до начала подфазы. Тогда же вернуть переключатель языка: при трёх и больше языках одного браузера мало. Перевод строк в `messages`, локаль в профиле и письмах, без смены `PRODUCT_NAME`.

## P-TELEGRAM. Уведомления в Telegram

Бот платформы уже есть (вход, D217), аккаунты связаны с Telegram (D230). Следующий шаг — третий канал уведомлений рядом с «в приложении» и «почтой»: отклики, взаимный интерес, дайджест (9B), оповещения по поискам (D234) приходят сообщением от бота. Нужно: webhook бота, `/start` с одноразовым кодом для подтверждения, канал `telegram` в настройках 9A, отписка командой. Без рассылок и рекламы.

## P-COMPANY. Подписка на компанию

Кнопка «Следить» на странице компании: новые вакансии этой компании — в тот же ежедневный канал, что оповещения по поискам (D234). Счётчик подписчиков — работодателю в статистике.

## P-SALARY. Зарплаты по навыкам

Публичная страница `/salaries/[skill]`: медиана и разброс вилок своих вакансий по навыку и уровню, только при ≥ 10 сравнимых вакансиях (D4, D5), без данных импорта, если источник запрещает. Хорошо индексируется и приводит кандидатов.

## P-ADMIN. Нормальная админ-панель

Навигация, «Компании», карточки пользователя и компании, поиск и фильтры в списках, обзор с просроченными элементами (D221–D224, в работе у Hermes). `/admin/metrics` встраивается в общую навигацию после этого.
