## D31 — npm package name

The workspace directory name is not a valid npm package name (spaces and capitals). The package name is `intgetion-job-list`. The product name stays `INTGETION JOB LIST` (D1).

## D32 — облачный Supabase для разработки

Локальный Docker на машине разработчика невозможен: виртуализация недоступна. Разработка идёт на облачном проекте Supabase `intgetion-dev`. Ключи лежат только в `.env.local` и в git не попадают. Проверка «миграции с нуля» и интеграционные тесты выполняются в GitHub Actions через `supabase start` (на раннере Docker есть). Локальный Docker не требуется.

## D33 — автономный режим

Заменяет пункт 1 раздела 0 («одна подфаза = одна сессия») и пункт 6 в части остановки на внешнем ключе.

1. Подфазы раздела 22 выполняются подряд, без ожидания команды между ними.
2. Переход к следующей подфазе — только если DoD (раздел 23) текущей выполнен полностью: lint, typecheck, test, build с кодом 0, P-тесты подфазы зелёные, коммит запушен, CI на GitHub зелёный (`gh run watch`). Красный CI чинится до перехода.
3. После каждой подфазы — запись в `MISSION_LOG.md` по шаблону раздела 0 и отдельный коммит `<код подфазы>: <кратко>`. Отчёт в чат — 5–10 строк на подфазу.
4. Секреты, которые агент может создать сам, он создаёт сам и пишет только в `.env.local`: пароль роли `app_rw` (случайный; `ALTER ROLE` через `DATABASE_MIGRATION_URL`; `DATABASE_URL` — Session pooler, пользователь `app_rw.<ref>`), `CRON_SECRET`. Значения секретов в чат и в git не попадают.
5. Если подфаза требует внешнего ключа или решения пользователя (`ANTHROPIC_API_KEY` в 7A, `RESEND_API_KEY` в 9A, founder approval в 8B, любой пункт раздела 25): сделать всё, что возможно без него (интерфейсы, тестовые двойники, тесты); пометить подфазу `BLOCKED` в `MISSION_LOG` с тем, что нужно от пользователя; перейти к следующей подфазе, у которой все зависимости (колонка «Зависит от») в статусе DONE.
6. Полная остановка и ожидание пользователя — только если не осталось ни одной доступной подфазы; нужно действие с риском потери данных в облачной БД (кроме миграций вперёд); тесты не удаётся сделать зелёными после 3 честных попыток.
7. Запреты раздела 24 действуют: не ослаблять тесты, не делать код V2/V3, не выдавать заглушки за реализацию.

## D34 — роль миграций на хостинге

Пароль встроенной роли `postgres` на Supabase нельзя сменить SQL-ролью `postgres` (это может только superuser). `DATABASE_MIGRATION_URL` — session pooler, пользователь `migrator.<ref>`. `DATABASE_URL` — session pooler, пользователь `app_rw.<ref>`. Пароли только в `.env.local`. Для не-loopback TLS в клиенте `rejectUnauthorized: false`, потому что локальная цепочка сертификатов не доверяет пулеру.
